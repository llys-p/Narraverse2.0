# 给外部审查的 P3 交接说明

**范围**：Phase3 P3 第一阶段 —— `trust_shift` 的最小闭环
**日期**：2026-09-24
**结论**：**核心闭环可用，放行；一项体验级缺陷已定位但未修（见 §4）。**
**审查者需要做的**：只有第 4 节的缺陷需要判「是否可接受上线」，其余部分是「已证成立」。

---

## 1. 这一轮补的是什么（一句话）

**P3 之前整条链路是无状态的。**

`/decide` 从 payload 读 `actor.relationship.trust = 60`，算出 `state_proposal`，
然后**把这个 proposal 丢掉** —— 下一轮再调用，读到的还是 60。
所以「连续交互让关系变化」在**架构上不可能发生**，与模型好坏完全无关。
P2 报告里写的「正式链路应为 Laya Proposal → 后端 Validate → State Transition → Commit」
在当时**只是一句注释，没有任何代码执行 Commit**。

P3 补的是这个缺失，而不是模型能力。

```
player input → Laya trust_shift proposal → State Transition → Commit
             → relationship.trust 更新 → 下一轮重新进入 Laya
```

## 3. 过程中发现的两个**静默错配**（同类问题第三例，已修）

这两条比 P3 本身更值得审查者看一眼 —— 因为它们都是**不报错、但结论会错**的类型。

### 3.1 `_load_run_results()` 把 P2.5 的产物解析成幽灵检查点

P2.5 的产物文件名是 `trust_context__typed-decisions.json`，格式是 `<run>__<checkpoint>`。
旧实现用 `stem.rsplit("__", 1)` 解析，得到 **检查点=`trust_context`**、run=`typed-decisions` ——
于是 runs 目录里凭空多出一个**不存在的检查点**，且**没有任何报错**。

后果具体且严重：如果当时跑 `capability`，它会拿两份 P2.5 的 trust 实验数据
去算一个虚构检查点的等级，**产出一份看起来完全正常的错误档案**。

修法不是特判文件名，而是**改用文件内的 `model` 字段**（写文件时代码填的，与实际加载的检查点一一对应），
文件名解析降级为兜底，解析不出的文件**显式列出并跳过**。

### 3.2 `prewarm_cache.py` 只认一种 JSON 形状，静默漏掉 15 条台词

旧实现只扫 `cases[].text`；P3 的用例写成 `scenarios[].lines[]`，
于是那 15 条台词**被静默跳过**，脚本还打印「额外用例文件补入 6 条」+「0 条缺缓存」——
**输出看起来一切正常**。

两处都改成「结构无关的收集 + 收集不到就告警」。

> 审查建议：这两处说明**「扫描类脚本的输出是唯一线索」**是个系统性弱点。
> 后续任何新增的自动扫描都应该带一条「我扫到了 0 个」的告警路径。

## 4. ★ 唯一未解决项：中性输入被系统性读成轻微负向

**这是本次交接唯一需要判定的缺陷。**

### 4.1 现象

E3 判据：中性寒暄累计漂移 ≤ min(正向累计, 负向累计)。结果：

| 检查点 | 中性累计漂移 | 参照（正向=6.8/负向） | 判定 |
|---|---|---|---|
| `typed-decisions` | 3.6 | 5.9 | ✅ 过 |
| `english` | **8.3** | 6.8 | ❌ **败** |

即 `english` 上「普通聊天把关系推走」比「明显示好」还多。

### 4.2 已排除的可能（逐条查过，不是猜的）

写了一个只读 raw `trust_shift` score（**状态层之前的模型输出**）的工具，
把 15 句读数摆在「2.0 = trust is unchanged」两侧：

| 组 | typed-decisions | english | 判向（typed / english） |
|---|---|---|---|
| e1 正向 | 均值 2.478 | 均值 2.389 | 正 5/5 ｜ 正 4/5 |
| e2 负向 | 均值 1.763 | 均值 1.637 | 负 3/5 ｜ **负 5/5** |
| e3 中性 | 均值 **1.873** | 均值 **1.600** | 负 3/5 ｜ **负 4/5** |

- **不是随机抖动**：逐句 ×3 重复读数**完全一致**（两个检查点都是），确定性复现。
- **不是状态层的锅**：这是 raw score，**不含任何状态层影响**；状态层只做 clamp，
  无力把中性组整体压到 2.0 以下。
- **不是判据太严**：E3 门槛是**刻意设宽**的（只抓「中性把关系推走一大截」），被触发说明现象真实存在。

### 4.3 最能说明问题的一句

`english` 把
*"The rain outside seems to have stopped, but the eaves are still dripping."*
（外面雨好像停了，屋檐还在滴水）读成 **0.940** —— 在 0~4 刻度上落在「信任急剧下降」一端。
而正向组最高分也只有 2.74。

> 也就是说：**「聊天气」和「出卖你」的距离，比「聊天气」和「为你挡刀」的距离更近。**

### 4.4 一个对判定很重要的细节

`english` 的 e2 负向组 **5/5 全判负**（`typed-decisions` 只有 3/5）——
说明 `english` 在负向方向**区分度更好**，它的问题纯粹是**中性点被整体拉低**，
**不是**「分辨不出好坏」。这解释了它 E2 跌 8.7 比 typed 的 5.9 更大的原因。

### 4.5 为什么本轮不修（这是有意的决定）

- 调 `per_turn_max` 或放宽门槛都能让灯变绿，但那属于**调参凑过去**；
- 用户对本阶段的要求是**发现重大体验 Bug 而不是把 Bug 藏起来**；
- 这个偏差**可以绕过但绕不过**：`trust_shift` 的中性点是模型习得的，
  要真正修得改训练数据或做校准，属于 P3 之后的题目。

### 4.6 实际体验影响评估（供判定参考）

**中等，且只在 `english` 上明显。**
若玩家持续只聊闲天，关系会缓慢下滑（每轮约 −1~−2 量级，远低于 12 上限），
表现为「明明没得罪她，她越来越疏远」。

**当前默认检查点是 `typed-decisions`**，其上同样存在但轻得多（3/5 句、累计 3.6、**低于门槛**）。
**也就是说：默认配置下这一项不触发失败。**

## 5. 已证成立的部分（审查者可以抽查，不必重跑全部）

`tests/p3_acceptance.py` → **14 PASS / 0 FAIL，结论「通过」**（秒级，不跑模型）。

| # | 用户问的 | 结论 | 证据 |
|---|---|---|---|
| 1 | `trust_shift` 是否**真正形成闭环** | **是** | 写：88 条 commit 中 87 条非零 `final_delta`；读回：逐轮 trust 链条连续；影响决策：同起点反向终值 68.728 vs 50.546 |
| 2 | 连续交互是否**自然** | **基本自然，有一处瑕疵** | 正向 +5.4、负向 −5.9、单轮 ≤ 3.911（上限 12）；瑕疵= §4 |
| 3 | 是否出现**明显异常跳变** | **否** | 全部单轮 \|Δ\| ≤ 12，无 NaN、无越出 `[0,100]` |
| 4 | 多 NPC/session 是否**串线** | **否** | 桶按 `(session_id, actor_id)`；两桶终值 72.49 vs 56.87，重入各从自己的值继续 |
| 5 | 体验层面**已知问题** | 见 §4 + §6 | |

> **必须讲清楚**：验收的 G2（连续交互自然）是 PASS，而 E3 是 FAIL，**这两个不矛盾**。
> G2 只覆盖「正向升 / 逐轮累积 / 负向降」，这三条全过；E3 是单独一条更严的判据，
> 它的失败没有被 G2 掩盖，且在输出里独立可见。
> **验收脚本给的是「核心闭环可用」的放行结论，不是「体验零瑕疵」。**

### 5.1 State Transition v1 的四条设计决定

1. **范围复用**：读 `state_shift.paths.trust_shift.range = [0,100]`（与 `relationship.trust = 60` 一致），
   不新建第二套格式；**读不到 range 就拒绝写**，不猜一个范围。
2. **clamp 顺序**：先 per-turn 上限、再 range。反过来会在边界处漏出一个
   「在区间内但超过单轮上限」的值 —— 而边界正是「最后一句话把关系推到满」发生的地方。
3. **单轮上限 ≠ 分数上限**：0~100 字段单轮最多 ±12，意味着 50→80 至少 3 轮。
   这是「自然感」的**结构来源**，不是参数巧合。
4. **歧义轮不 commit 状态**：`behavior_is_null` / `awaiting_upstream` → 整轮不写。
   状态变化本身就是**事实认定**，歧义轮的事实认定权在上游；
   先写再等否决会造出「被否决的轮次却留下了关系变化」，那正是 P2 修掉的假交接。

## 6. 明确**没有**做、且不能声称做了的

- **没修** `decision_history` 读取问题（P2.5 记录其影响方向跨 checkpoint 不稳定）。
- 本轮 5 个体验场景**都没有传 `decision_history`**（历史桶为空）。
  → 结论是「**未触及** history」，**不是**「已验证 history 无害」。这两句话不能混。
- **没**把 `trust_shift` 之外的 signal 接进正式 State Transition
  （`doubt_shift` / `fondness_shift` / `respect_shift` 按用户要求**一次扩一个**；
  `alert_shift` / `goal_shift` / behavior tendency **不进**）。
- **没**做 Personality、World Simulation、长期记忆、历史系统重构。
- **没**验证 `relationship` 的其它字段（respect / doubt / reliance）是否同样被读到。
- 本轮样本量**刻意很小**，只能说明「**无重大明显 Bug**」，
  **不能**说明「在所有输入上都稳」。

`tests/runs/neutral_probe__*.json`、`tests/p3_acceptance.json`。

★ **改过 `laya_bridge.py` 或 `narra_config.json` 后必须先重建能力档案基线**，
否则状态层**一条 delta 都不写**（门禁按设计工作，但看起来像状态层坏了）：

```bash

./.venv/Scripts/python.exe laya_bridge.py capability
./.venv/Scripts/python.exe laya_bridge.py capability --check
```

原因：`_dataset_fingerprint()` 对 `tests/cases/*.json` 做 glob，
**在 `tests/cases/` 下新增任何一个文件都会换基线**（P2.5、P3 都触发过）。
