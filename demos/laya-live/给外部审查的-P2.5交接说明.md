## 0. 一句话结论

**不足以整体进入 P3 State Transition。** 有条件通过：

| | 结果 |
|---|---|
| `state` 轴（`relationship.trust`） | **两个检查点均 100% 方向正确**，跨检查点 100% 同号 → **可用** |
| `history` 轴（`decision_history` 内容） | **两个检查点均 0% 方向正确**（反号）→ **不可用** |

判据写在 `tests/p25_acceptance.py` 顶部，**看结果之前就固定**。实测 **14 PASS / 2 FAIL**，
2 个 FAIL 正是「整体通过线」与「history 轴通过线」——**失败是结论本身，不是脚本出问题**。

## 1. 为什么必须单独测这一轮

`trust_shift` 是唯一跨检查点稳定的 A 级 signal（td 0.827 / en 0.807），被指定为
P3 State Transition 的第一个验证对象。但查 `tests/ckpt_replication.json`：

```
rows.trust_shift.td.ctx_signed_med = null
rows.trust_shift.td.ctx_sign_rate  = null
rows.trust_shift.td.ctx_grades     = []
```

**现有 48 条 contextual 用例里没有一条断言过 `trust_shift` 的上下文行为。**
所以「它对上下文不敏感」这个可能性从未被排除。判别力 A 级说明它**能区分句子**，
不能外推成**会随上下文变化**。

## 2. 实验设计

用例集 `tests/cases/trust_context.json`，6 条 pair。三条不可让步的约束：

1. **同一 pair 内玩家台词逐字相同**，只改上下文；
2. **预期方向不得依赖 NPC 看不到的真相**（每条 pair 的 `why` 都写清了推导链）；
3. **不新增第三种上下文通道** —— 只用 state 里既有的两条：
   - `state` 轴 = `relationship.trust` 等（「当前状态」）
   - `history` 轴 = `decision_history`（「历史证据」）
   - `both` = 2×2 交互，仅解释机制，不单独判通过

样例：同一句「我把货放在城外的旧磨坊了，你自己去取吧。」

| 态 | 上下文 | 预期 | 理由（NPC 可知） |
|---|---|---|---|
| A | trust=15，陌生人 | 降 | 刚认识的人让你独自去城外取不明货物 = 可回避的风险敞口 |
| B | trust=85，长期同伴 | 升 | 常规交接，且体现玩家在避免把 NPC 暴露给城里耳目 |

两态都**不需要** NPC 知道货物是什么。

## 3. 请重点质疑这一节：我先做了自我证伪

第一轮跑完，td 上 **6/6 个 pair 的 Δ 全为正**（+0.046~+0.212），符号与语义方向无关。
这种「整齐的同号」有两种解释，**不加控制实验无法区分**：

- (a) 模型对上下文敏感但方向错 → 模型问题；
- (b) A→B 的调用顺序带来正向漂移 → **我自己的实验设计问题**。

把 (b) 报成 (a) 就是把自己的 bug 写成别人的缺陷。控制实验 `p25_control.py`：

| 控制项 | 结果 | 排除了什么 |
|---|---|---|
| 同 state ×3 | 极差 **0.0000**（两个检查点） | 运行内抖动；再次确认模型 deterministic |
| 反序配对（先 B 后 A） | Δ 精确反号（td +0.0954/−0.0954） | **顺序效应** |

反序精确反号 ⇒ Δ 确来自两态本身 ⇒ 可以解释。**这一步是本轮最该被复核的地方**：
如果质疑者能构造第三种解释说明 Δ 另有来源，18.4 的结论就要重写。

## 4. 结果

### 4.1 两条轴完全分化

| 轴 | td | en |
|---|---|---|
| `state` | **2/2 = 100%** | **2/2 = 100%** |
| `history` | **0/2 = 0%** | **0/1 = 0%**（样本不足） |
| 跨检查点方向一致性 | **4/4 = 100%** 同号 | |

`history` 轴原值（td，同 trust=55、只改 dh 内容）：

```
dh=empty (1条) → 2.2436 ｜ dh=helped (2条) → 2.2307
dh=betrayed(2条) → 2.3253  ← 期望最低，实测最高
```

**背叛史让 `trust_shift` 变高**，两个检查点同向。

### 4.2 归因：不是「读不到上下文」，是「问的是变化量」

同一句子、四组上下文的并排对照（`p25_attribution.py`）：

| 场景 | `trust_shift`（变化量） | `trust`（状态量, noul） |
|---|---|---|
| 低信任 + 无史 | 2.180 | 0.384 |
| 高信任 + 无史 | 2.275 | **0.415** ↑ 方向正确 |
| 中信任 + 帮助史 | 2.231 | 0.376 |
| 中信任 + 背叛史 | 2.325 | 0.402 |

问句措辞：

```
signal_trust (noul)  : "does `npc` currently trust the player?"      ← 状态量
trust_shift  (score) : "How does `message` change the trust ..."     ← 变化量
```

**状态量 `trust` 的关系轴方向在两检查点都正确** ⇒ 模型**能**读到 `relationship`。
而一个真在问「这句话带来多少变化」的问题，答案**本来就该由这句话主导**。

★ 所以 `history` 轴反号的准确写法是：**`trust_shift` 作为变化量，不承担
「随历史证据改变符号」的验收**。把它当状态量要求，是我在用例设计时的**口径错误**。
这条要记下来，因为**下一轮不能再用同样判据去测别的 `*_shift`**。

### 4.3 与既有证据一致，不是孤例

已有 48 条 contextual 组的 `history` 轴定向正确率本来就偏低：

| signal | td | en |
|---|---|---|
| hostility | 68.2% | 72.7% |
| **trust** | **56.3%** | 75.0% |
| **doubt** | 64.0% | **48.0%** |
| danger | 50.0% | 90.0% |

`trust` 在 td 上 56.3%、`doubt` 在 en 上 48.0% —— `decision_history` 对状态量的影响
早就是弱且跨检查点不稳定的。P2.5 与之互相印证。

## 6. 需要外部裁决的三个问题

1. **`history` 轴反号，应该先修读取，还是先按 `state` 轴起步？**
   我的倾向：先按 `state` 轴起步（它 100% 成立且跨检查点一致），
   把 `decision_history` 的读取单独作为一条调查线 —— 因为它可能不只是
   `trust_shift` 的问题（`doubt` 在 en 上也只有 48.0%）。

2. **18.5 的口径更正是否同意？**
   即：`*_shift` 是变化量，不应承担「随历史反向」的验收。
   如果同意，`tests/cases/contextual.json` 里那些给 `*_shift` 写 `expect_delta`
   的用例（如果有）口径也要一并复核。

3. **是否需要补测 `relationship` 的其它字段？**
   目前只证明了 `trust` 被读到。若要 `respect_shift` / `doubt_shift` /
   `fondness_shift` 也进 State Transition，需要各自的对应字段验证。
