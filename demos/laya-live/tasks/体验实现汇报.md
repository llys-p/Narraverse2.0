# Laya Demo 体验实现汇报（v2026-09-25）

> 用途：交用户转给其他 AI 讨论「还要添加什么功能」。本文基于**真实运行**（CUDA 桥 8131，
> typed-decisions 检查点 + DeepSeek 云端），非规划稿。所有改动已本地留档（分支 `laya-p2-safe`）。

## 1. 一句话总结

Demo 已跑通「一句话 → Laya 判断了什么信号 → 数值变化（可预览/可提交/可拒绝）→ 云端按状态
生成有主动性的回复」的完整可解释闭环；页面把每一步都可视化，并严格区分「未提交预览 / 已提交 /
仅参考」。

## 2. 体验层：已实现（都在页面上可操作）

### 核心链路（P2 协议面板）
1. **读取**：获取服务端权威快照与版本（不看本地缓存）。
2. **Analyze**：填一句台词 → ② 栏显示**逐句判断链路**：
   ```
   玩家原话：「你到底想干什么？」
   ● doubt_shift（Laya 读出 raw=2.368）→ relationship.doubt
     提议 2.368 → 预览 30 → 32.368（将 applied 2.368）
   · trust_shift（辅助信号，只参考不改）
   · fondness_shift（辅助信号，只参考不改）
   已测定读数：doubt_shift=2.368 · …
   ```
3. **Commit / Reject**：提交一次只 + 一次；① 栏变化项**绿色高亮 + 增量**（如 `doubt 32.368 +2.37 基准 30`），未变项灰色并标注基准；Reject 则事件关闭、数值不动。
4. **云端回复**：按「已提交状态 + 参考信号」生成中文台词（P3 proactive），可以自然追问/表态，不替玩家决定；标注 `state_source=committed, commit_allowed=false`（不改变状态）。

### 数值可视化
- ① 栏每个字段：`基准值 → 当前值 + 进度条 + 变化量`；首次读取锁定模板为基准（刷新保持）。
- 颜色语义：绿=相对基准已变/刚提交，灰=未变，黄=待提交预览中。
- 面板横向紧凑（三栏限高滚动），不再纵向拉长。

### 旧玩法
- 原 `/decide` 演示保留可切换；旧内容与新 P2 面板共存。

### 真实体验记录（浏览器 5/5 步通过，无 JS 报错）
- 读取 OK → Analyze（~25s 出链路）→ Commit（①栏变 32.368 绿）→ 云端回复（~20s 出中文台词）✅

## 3. 技术层：已实现

- 协议端点：`/analyze`、`/commit_state`、`/reject_analysis`、`GET /analysis/{id}`、`GET /state`（带 `state_version`）、`/narrate mode=analysis|upstream`；旧 `/decide /turn /commit /reset` 共用锁与版本。
- 核心机制：版本 token（epoch/gen/rev）；新旧提交互斥（stale 拒 409）；**幂等重试回执**（replayed）；TTL 600s/回执 3600s；容量 429；**事务回滚**（异常无部分写入）；多线程锁；事件级去重（`EVENT_*` 409）。
- 安全门禁：引擎身份 503（防 fallback 冒充）、NaN/Infinity 守卫（三层）、传输层校验（CL/顶层对象/结构化错误码）、翻译 fail-closed + 冻结基线、`reference_only` 禁空 Commit。
- 叙事：`_build_narrate_prompt` proactive 分支（允许追问/表态/有限线索，显式「信号≠事实，不改数值/不替决定」）；legacy 分支语义未动。
- 测试（零模型单元）：P1 36 + P3P2 54 + P2B1 86 + P2B2 22 + P2C 17 + P3A 17；**P3-B 真实云端对照 13/13**（6 组 × 无/有信号，证据在 `_diag/`）。
- 基础设施：CUDA（RTX 4060）、`LAYA_MODELS_DIR` 指向既有权重、`.env` 密钥注入、`LAYA_TRACE` 诊断门。

## 4. 未实现 / 已知缺口（两部分，供讨论）

### 体验层缺口
1. **只有 doubt 一个维度会变**（typed-decisions 唯一 active 信号；页面已如实标注）。想体验更多维度需 `english` 检查点（fondness 可写）另起一桥对照。
2. **属性/世界判定完全缺失**：当前只有关系/情绪数值，没有「力量 5 能搬多重、角力数值差+概率压制」这类语义锚点与对抗裁决。
3. **云端主动性停留在追问/表态**：未到「主动抛出剧情钩子/推进支线」程度（P3 只过小对照）。
4. **长线体验未正式验收**：30–50 轮连续对话后人物变化累积未试玩评审。
5. 场景输入（context.scene）、多角色切换页面上没有入口（接口已支持）。

### 技术层缺口
1. **100 条固定稳定性资产**未建（输入+冻结译文+期望方向三件套，优先本地校验）——P3 小样本通过后的正式基线。
2. 真实模型长会话并发/审计未全量验证；浏览器端到端自动化未入库。
3. 内存态（重启即失）；单进程单机（多进程/持久化未支持）。
4. 待统一审核并推送（11 个本地提交中 9 个未审）。

## 5. 候选讨论项（抛给其他 AI）

- **A. 属性语义基准 + 对抗判定**：为数值建立世界语义档位（「5 点力量=能搬动多重的对象」等）与「数值差→概率」的对抗裁决表；明确分层（判断归 Laya、裁决归规则层）。
- **B. english 检查点对照体验**：第二个桥跑 `english`，让 fondness 也可写，对比两种信号体感。
- **C. 100 条稳定性资产**：按 plan §6.3 建基线。
- **D. 场景/多角色入口**：页面上补 scene 与角色切换输入。
- **E. 主动性增强**：P3 后续——让云端能给出「下一步线索/钩子」建议（需口径与对照）。
- **F. 体验量化**：把「一句变化有多大」做成每步的“预期 vs 实际”提示（基于当前档案可信度）。
