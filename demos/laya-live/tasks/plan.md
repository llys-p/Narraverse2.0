## 3. 关键决定

1. **保留新版提交边界**。旧版更“有反应”的显示与台词可以恢复，但浏览器本地加减不能成为真实状态来源。
2. **三类输出分开**：当前已提交状态、本轮变化预览、参考信号。C/auxiliary 仅供参考；disabled 不参与创作；R/semantic_review 暂不参与创作，不静默取反。
3. **能力不因修环境而升级**。typed-decisions 的真实状态闭环先用 doubt；trust/fondness 仍不能直接写。english 单独成组，不能从两个检查点拼出一份“全能档案”。
4. **情绪表现与情绪状态分开**。当前没有经过验收的 emotion 标签能力。云端可表现生气、犹豫、好奇，但不能把这种文学描写冒充 Laya 已验证标签或权威数值。
5. **主动性归云端**。DeepSeek 可根据人物目标、对话和可信信号追问、拒绝、转移话题、提供有限线索；不恢复 Laya 强选动作。重大秘密、场景切换和世界事件仍受剧情约束。
6. **有意义的反馈不要求每句话都涨跌**。零变化/unknown 必须合法；不能为了“看起来活”强制制造数值变化。
7. **不做多 Agent 平台化建设**。P2 仅实现 Demo 所需的一次分析、一次确认、一次提交；接口应能被多个只读查看者使用，但不建设 Agent 调度系统。

取舍：回退旧版最容易重现动画和变化，但会重新引入先写状态、猜行为的问题；直接放开全部信号也会制造未经验证的数值。本计划选择恢复可解释的反馈与云端表现，保留权威状态门禁。

### P1-A 实现（其他 AI，小范围）

- 明确模型目录和冻结基线缓存路径；启动不依赖手动 monkey patch，不硬编码个人机器路径进业务逻辑。
- dataset 原始指纹优先；只有按文档允许的 CRLF→LF 处理后**完整匹配原档案**才能兼容放行，报告兼容原因。内容改动、增删用例仍拒绝。
- 档案检查和基线译文读取使用同一冻结源；缓存缺失/损坏/子集漂移必须 fail-closed，禁止在线补译。日常玩家新输入可沿用原翻译功能，但不得写回基线或覆盖已有冻结译文。

预计改动：桥接文件、聚焦测试文件、可选启动辅助、README、协作日志；如需更多独立模块先拆任务。

### P1-B 验收（其他 AI 生成证据，Codex 复核）

不载入模型权重、不调用付费接口；测试全部使用临时目录/内存副本。要求：LF/CRLF 等价通过；真实用例内容改变拒绝；缺译文/修改译文拒绝；未知或不匹配 checkpoint 拒绝；两检查点 active 集合不变；冻结资产哈希不变；无档案仍不产生 writable delta。

原有 `tests/p3p2_unit.py` 作为针对性回归，报告真实计数，不硬写必须是 54。禁止运行 capability 生成、signalmetrics、重预热或重基线。

**交付即停止**：给出 commit、文件清单、检查结果和已知限制。Codex 审查后才进入 P2；P1 不改 `/analyze`、叙事表现或 UI 提交语义。

## 5. P2：恢复可信的数值交互

### P2-A 协议定稿（Codex，依赖 P1）

先复用已有协议设计任务的产物（若存在），核对代码后定稿，不让两个 AI 各写一套。

- `/analyze` 返回 analysis_id、base_state_version、signals、state_proposal、capability、evidence、can_commit；字段类型与错误码在实现前冻结。
- Pending 绑定会话/角色/输入/基础版本/模型与档案，Commit 仅接受服务端引用；不能靠客户端自传 delta。
- 对重复、并发、过期、拒绝、重启失效以及 profile 变更明确处理。内存 Demo 重启可整体失效，不假装具备持久化恢复。

本项是后续关键设计工作，**不因 P0 完成而宣称协议已定稿**。

### P2-B 状态提交实现（其他 AI，依赖 P2-A）

实现纯分析和原子提交，确认状态版本，记录前后值；新状态判断不再依赖 NPC 必须选出行为。旧 `/decide`、歧义云端接续等兼容入口保持可用，复用同一状态写入层。

验收：分析任意次数均不改状态；同一结果最多应用一次；版本冲突/过期/翻译失败/不可写信号均无写入；一次合法 doubt 提交后下一轮读取新值。用构造 Proposal 的测试证明机制，用真实样本另验判断质量，不能相互替代。

### P2-C 最小页面闭环（其他 AI，依赖 P2-B）

用服务端已提交快照更新数值，移除正常交互中的本地权威加减。显示本轮预览和“未提交/已提交/未采用”，保留手动 Commit；参考信号独立展示其等级/来源。歧义云端回复仍不能自动放行状态提交。

验收：点击分析不变真实值，提交一次只变一次，刷新/下一轮保持服务端值；页面不存在预览已变而服务器未变却标“已更新”的情况。每项预计 3–5 文件，小步提交。

## 6. P3：恢复角色主动性与逐句反馈

### P3-A 创作适配（Codex 定边界，其他 AI 实现）

将已提交状态、允许参考的信号、人物目标、当前场景和原始对话分块送入 DeepSeek。允许自然追问、立场表达、有限线索和话题转换；调整旧提示词中一律禁止结尾提问的规则，但不强制每轮提问或推进。

提示词要区分“角色可以这样表现”与“事件已经发生”；不会因为一个分数高就泄露秘密、修改数值或替玩家决定。保留云端失败的明确反馈。

### P3-B 小对照，再扩样本（其他 AI）

先由 Codex 选定 6 组场景（正常闲聊、示好、质疑、威胁、拒绝、情节线索），每组比较无信号/有信号两种输入，**首批最多 12 次云端生成**，不调用全套 benchmark。若不清晰，先报告原因，不自动扩大付费请求。

评价：是否回应原话、保持人物、主动但不抢玩家决定、信号差异能否合理影响语气/策略、是否擅自改变事实。由用户确认“像旧版一样有反应”的主观体验；不能用固定种子或数字阈值假装已经证明创作质量。

小样本通过后再单独下发 100 条固定稳定性资产工作：输入/冻结译文/期望方向或允许 unknown，共同纳入基线；优先本地校验，不把 100 条都重复送云端。此为后续任务，不包含在 P1 授权中。

## 7. 成本与协作纪律

- 其他 AI 做实现、测试编写和批量执行；Codex 只做关键设计、抽查证据与最终放行。用户手动转交提示词，不自动创建更多执行任务。
- 每阶段返回短摘要：commit、改动文件、跑过的命令、真实 PASS/FAIL、未验证项、保护资产是否改变。原始证据留本地文件，避免聊天中贴大量日志。
- 不重复读取整仓库；先根日志最新条目、当前阶段计划、涉及源码。变更点超出提示词范围先说明具体原因。
- 不重装环境、不重新下载模型、不同时加载多个检查点；模型或云端运行次数到上限即停并报告。
- **运行设备按实测选择，不预设 GPU 必然最快**：P1 零推理；后续先复用 P0 小对照结果。改变设备/精度/线程数需同 checkpoint、固定英文输入和题集、预热后比较；分别记加载与稳态时间，检查输出差异。只选择已测配置中的合适方案，不宣称穷举最优。
- 必须核对**实际模型参数设备**以及预测前后 agent.device。环境变量、GPU 利用率、当前 `/health` 的设备标签都不能单独证明运行设备。预期 CUDA 却回落 CPU 时停止报告，不允许带着错误的 GPU 标签长跑；明确测得且选择的 CPU 配置可以使用。
- 本机候选解释器：`C:\Users\11\WorkBuddy\2026-09-23-11-11-35\laya-live\.venv-cuda\Scripts\python.exe`。该环境也可以显式跑 CPU，以便保持 torch/Laya 版本一致地比较。路径运行前核实，不误用另一环境改变实验条件；纯文件哈希/无模型单元测试不受此限制。
- **模型调用陷阱**：保持每进程只常驻一个 checkpoint；先查当前服务是否已加载，避免重复占显存。Laya 输入保持英文，沿用状态 token 预算与截断诊断；中文不直接送英文检查点。重复输入稳定不代表重译稳定，已有冻结译文不重译。choice 分数/熵和未校准 confidence 不当作“人物行为真实概率”。
- **云端调用陷阱**：复用现有 model ID、超时、`max_tokens` 和 `<line>` 解析，不照抄模型显示名；空正文需区分预算耗尽/上游错误，保留有限重试，禁止无限重试或把推理内容展示成台词。环境检查只能报告密钥是否存在，不能输出内容；历史明文凭据不复制进提示词、报告或 Git。
- 先做 1 次短预热和 1 个代表输入，再决定是否跑批；分别记录加载/翻译/推理/叙事耗时，不能把冷启动延迟当稳态延迟。此为后续已授权推理阶段的执行顺序，不授权 P1 跑模型。
- 本地已有 worktree：`D:\Narraverse2.0-wt-laya`。其他机器使用包含保存点的独立 checkout；不改 `D:\Narraverse2.0` 的 main，不覆盖用户未提交内容。

- 冻结缓存、capability_profiles、cases、旧 runs、narra_config 的基线不在 P1 修改范围。无真实基线不一致证据，不重新评测。
