# Demo 交互整体规格（v1，待确认后按此重构）

> 目的：结束「两个对话框／一堆按钮」的割裂局面。先定整体体验，再谈界面与代码。
> 原则：**对话是主视图，判断是后台，细节是折叠**。

## 1. 定位一句话

打开页面 = 一个**对话窗口**：玩家打字、NPC 回应、关系数值随之自然变化；
「说了什么 → Laya 判断了什么 → 哪个数值变了多少」作为**对话的附属信息**自动出现，不需要玩家懂机制或按任何流程。

## 2. 页面只有四件事（自顶向下）

| 区域 | 内容 | 说明 |
|---|---|---|
| ① 对话区（主） | 玩家与 NPC 的气泡对话 | 唯一事件发生地 |
| ② 每句影响标注 | 在本句回复气泡下方小字：`这句让 怀疑度 +2.4 → 32.4` | 自动出现，绿色变化/灰色无变化 |
| ③ 角色状态栏 | trust/doubt/fondness… 当前值 + 相对基准的变化 | 右侧一列，随对话滚动更新 |
| ④ 机制明细（默认折叠） | 「看看 Laya 怎么判断」：判断链路/信号/参考（原 P2 三栏 + Decision Engine 日志） | 想搞懂机制的人自取，平时不出现 |

## 3. 唯一对话流程（全自动，不需要手动按钮）

```
玩家 Enter 发送台词
  → ① 翻译（冻结基线优先，fail-closed）
  → ② Laya 判断（doubt_shift 等信号 → raw）
  → ③ 状态变化【自动提交】：按协议 Commit 一次（数值 +1 版本）
  → ④ 本句影响标注 + 状态栏更新（可见「怀疑度 +2.4」）
  → ⑤ 云端回复（按新状态与参考信号生成，主动但不变数值）
```
**玩家只需打字 + Enter。** Commit/Reject/云端回复不再要求手动点按。

## 4. 原 P2 面板与按钮的去向

- **四个按钮（分析/提交/拒绝/云端回复）从主操作区移除**，降级为「手动单步调试」：
  折进④机制明细区，供演示/调试需要「一步步来」时使用（默认折叠、平时看不到）。
- **原 P2 三栏**（基准→当前 / 本轮判断 / 参考信号）并入④机制明细；其中「①基准→当前」是可常开的状态栏来源。
- **自动提交开关**：规格默认「自动提交（对话流）」；如演示需要「决策式确认」，在④里提供 `自动提交 开/关` 开关——关掉后变成「每句预览→手动确认」，但**默认开**。

## 5. 旧 Decision Engine 日志

默认折叠（仅开发者/排查时展开），不参与正常对话。

## 6. 与协议层的关系（保持不变，只动表现层）

- 后端接口不变：`/analyze`、`/commit_state`、`/reject_analysis`、`/narrate mode=analysis`；
- 自动流程 = 前端依次调用 analyze → commit_state → narrate（一个 `send2()` 封装）；
- 版本冲突/超时/参考信号照常提示，不破坏锁定与幂等语义。

## 7. 本次重构范围（确认后执行）

1. 顶部输入 Enter = 自动走完整链路（取代「发送」旧流与四按钮手动流）；
2. 对话气泡下加「本句影响」标注；右侧/对话侧加状态栏（实时相对基准）；
3. P2 三栏 + Decision Engine 折叠进「机制明细」；
4. 保留手动单步（分析/提交/拒绝/云端回复）与自动开关于细节区；
5. 浏览器端到端验证一轮。

## 8. 待你确认的取舍

- **状态栏位置**：对话右侧固定一列 vs 折叠在机制明细里（推荐右侧常开小栏）；
- 机制明细默认折叠是否 OK。
