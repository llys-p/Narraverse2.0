## 2. 阻断 1 · DeepSeek API key 失效

### 事实

```
GET https://api.deepseek.com/user/balance
→ 401 {"message":"Authentication Fails, Your api key: ****d4f0 is invalid"}
GET https://api.deepseek.com/models
→ 401 同上
```

### 危险之处：它是**静默**失效，不是报错

`translate_to_en` 把异常吞掉后 **返回中文原文**（`src="none"`）：

```
'今天天气不错。'               → 'Nice weather today.'      src=llm   ← 成功
'风好像比刚才大了，窗户在响。'  → '风好像比刚才大了，窗户在响。'  src=none  ← 失败，原样返回
```

★ **首次调用可能成功、随后失败** —— 表现为随机、间歇，极易误判成「模型今天不稳定」。

后果链条：
中文原文进 state → 英文 ModernBERT 收到非拉丁脚本 → **高置信 + 零准确**
（README 自带基准：高棉语 0.952 置信 / 0.000 准确）。
这正是本项目从 Phase A 起反复标记的**最危险失败模式**：不报错、看起来在跑、结果全错。

### 实测症状

```
decide('第一次见，我从北边来，路上不太平。')  26.3s
→ trust 60（未变）  state_commits []  state_skipped []
```

注意 `skipped` 也是空的 —— 说明它**不是被门禁拦下**，而是根本没有产生可用 delta。
叠加档案 stale（阻断 2），两个原因都指向「静默不动」。

### 处置决定：**不修**

- 按项目铁律，凭证轮换是**账号问题，不是代码问题**；
- **绝不**在翻译失效时回退「直接用中文」—— 那会把静默错配固化成正常路径。
  `LANG="en"` 下宁可不动。

**恢复方式**：更新 `.env` 里的 `DEEPSEEK_API_KEY`，然后重跑
`tests/replication/prewarm_cache.py`（补齐 37 条新台词；旧 194 条已在缓存里）。

## 6. 关于中性死区的一个重要更正（**Task 1 的诚实结论**）

用户要求「先看当前实际 delta 分布，再选最小够用值」。照做之后发现：

**模型 raw `trust_shift` score 无法区分「中性闲聊」与「轻微有意义」。**

| 检查点 | 中性 raw 区间 | 有意义 raw 区间 | 重叠 |
|---|---|---|---|
| english | 0.940 – 2.129 | 1.041 – 2.745 | **低端重叠** |
| typed-decisions | 1.648 – 2.162 | 1.431 – 2.809 | **重叠** |

⇒ 结论是**任何量级阈值或 raw 带都不可能根治**。四方案实测：

| 方案 | 做法 | 中性残留 | 有意义留存 | 评价 |
|---|---|---|---|---|
| A 对称带 | `w=0.30` 绕 2.0 | 76.5% | 87.4% | 几乎没用 |
| A′ | `w=0.40` | 55.9% | 87.4% | 需要很大带宽 |
| B 非对称带 | `[1.20, 2.05]` | 42.4% | **仅 70.1%** | 压住中性靠的是砍有意义 |
| C 零点平移 | zero 2.0 → c | **86–112%（更糟）** | — | 同时放大正向 |
| D 平移 + 窄带 | — | 同 C | — | 同上 |

**最终落地值**：`T=1.0`（拐点 `T=0.7` 为「每吃 1% 有意义换约 2% 中性削减」）。
`T=2.0` 会吃掉**近 6 成**有意义变化 —— 所以**没有**为了让测试全绿把死区调大。

⇒ 报告里的措辞必须是「**部分缓解，不是根治**」。这是 Task 1 的真实产出，
不是「已解决中性漂移」。
