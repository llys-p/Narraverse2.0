## 4. 新规划三类判断 × 现有能力映射（本分析的结论）

| 规划判断类型 | 最接近信号 | td | en | 结论 |
|---|---|---|---|---|
| **A. 关系状态判断** `trust_delta`/`affection_delta` | trust_shift / fondness_shift / doubt_shift | C / C / **A** | C / **A** / D | ⚠️ 接口可马上改，**但接口漂亮≠判断变准**：C 级信号返回的数不能标"可信" |
| **B. 情绪状态判断** `emotion∈[angry,sad,happy,fear,suspicious]`+intensity | 无 emotion；最近 danger=D | — | — | ❌ **从零开始**：需新造 benchmark 数据 |
| **C. 事件/剧情路由判断** `possible_trigger`+priority | investigate / confront / hostility | **R** / B / C | R / C / C | ⚠️ **必须先做 investigate 方向复核**（R 级），再谈接接口 |

**推论**：A 类是"把已有 C 级信号按新接口暴露"，要如实标注等级；B 类要立项造数据；C 类卡在一个语义问题上。**三类没有一类是"接一下现有能力就能上线"的。**

## 5. 新规划要点摘录（原文锚点，供后续施工对照）

- **三类判断字段**：A 关系（`trust_delta`, `affection_delta`, `emotion`, `confidence`）；B 情绪（标签 only，**不写文学性描述**）；C 路由（`possible_trigger` 候选如 `secret_reveal`/`conflict`/`comfort` + `priority`，**候选 only，LLM 决定**）。
- **删除/降级**：删 Laya 生成的剧情动作、自规划 NPC 目标、Laya 写的回复、复杂 agent 链；Proposal 降级为 **"State Delta + Confidence + Evidence"**。
- **保留**：`state → delta → commit → next turn read` 闭环；State Transition 校验/commit/history/rollback；测试框架（benchmark/validation/regression，目标调整为稳定性）。
- **§6 翻译缓存（原文）**："翻译缓存必须作为测试资产管理。固定：input.json / translation_cache.json / expected_output.json 三者共同组成测试基线。禁止：每次测试重新翻译导致输入漂移。"
  → **这是对 P3P2 选项 B（冻结缓存+版本控制）的 spec 级独立确认**——我方实测证据：temperature=0 重译仅 13% 逐字一致；缓存重建致 trust/fondness_shift A→C。
- **§7 架构图**：用户消息 → Laya Analyzer →（trust_delta / emotion / safety / event_hint / confidence）→ State Manager → 最新角色状态 → Claude/LLM → 最终剧情回复。
- **§8 API**：`POST /analyze`（in: `character_state`,`history`,`message`；out: `state_delta`,`signals`,`confidence`）；`POST /commit`（in: `character_id`,`delta`；out: 最新状态）。
- **§9 Phase-1 验收**：一条消息 → 结构化 JSON → 状态更新 → 下一轮读到新状态；**100 条固定样本**测格式错误率 / 状态一致性 / 重复输入漂移。集成价值：Claude 不再猜"NPC 是不是生气？"，而是收到 `trust -3 / emotion suspicious / event conflict`。
- **后续扩展**：respect, fear, loyalty, memory importance, safety judgement, lore consistency check。

## 6. 交互契约：现状 → 目标（改造落点核心）

### 6.1 现有路由契约（实测自 laya_bridge.py:2502–2789）

| 路由 | 方法 | 输入 | 输出/语义 |
|---|---|---|---|
| `/health` `/config` `/state` `/demo` `/history` | GET | — | 健康检查 / 配置 / Actor State / 演示页 / 最近 50 条历史 |
| `/decide` | POST | npc+玩家台词(+state) | **只 propose 不写历史**；响应带 `history_gate{stage:"proposed", committed:false}`；歧义轮 behavior=null |
| `/turn` | POST | 同上 | **快路**：decide + 自动 propose+commit（`commit_state=false` 可关）；响应带 `state_gate{stage:"committed"/"not_committed"}`；单人连续剧情用 |
| `/commit` | POST | **`turn_id`** | 提交门：把 /decide 的候选写进 (session, actor) 历史桶，语义="上游真的采纳了这轮" |
| `/narrate` | POST | behavior 或让其先 decide | 行为→台词（DeepSeek LLM）；**歧义轮返回 `awaiting_upstream:true` 不代选**；LLM 失败回落台词池（带 llm_error 线索） |
| `/world` | POST | 世界事件 | world_decide |
| `/reset` | POST | session_id/actor_id | 按桶清历史+Actor State（同桶同清） |
| `/predict` | POST | 任意 state+questions | 原始透传 ENGINE.predict（调 API 形状用） |

内部链路：中文输入 → `translate_to_en`（**缓存优先，fail-closed**）→ 16 题（score/noul/choice）→ gates 覆盖 → State Transition（proposal → deadzone → per-turn clamp → range clamp → Commit）→ 返回。

### 6.2 目标契约（spec §8）

```
POST /analyze   {character_state, history, message} → {state_delta, signals, confidence}
POST /commit    {character_id, delta}               → 最新角色状态
```

### 6.3 新旧差异对照

| 维度 | 现状 | 目标 |
|---|---|---|
| 判断与提交 | `/turn` 一步到底；`/decide`+`/commit(turn_id)` 两步 | **analyze 与 commit 显式分离**，commit 的对象是 **delta** 不是 turn_id |
| commit 语义 | 提交"历史桶候选"（turn_id） | 提交"状态 delta"（character_id）→ **名字撞了，改造时必须区分/复用要明确** |
| 行为与台词 | choice 出行为分布，/narrate 出 LLM 台词 | **删**：Laya 不出行为/台词，只出判断 |
| Proposal | 复杂行为提案+理由+行动计划+状态变化 | **State Delta + Confidence + Evidence** |
| 台词 | /narrate（DeepSeek） | 全归 Claude/LLM，Laya 只喂结构化状态 |

## 11. 铁律守则（违反 = 数据作废或档案被污染，接手前必读）

### 数据资产
1. **翻译缓存不可再生**：冻结基线 `tests/assets/translation_cache.json`（264 条，sha256 `ac954c9494cde48427b80091daab20f1b5c74ddb1c7c5c9aa46940a20652abc7`）。运行时仍读 `_diag/translation_cache.json`，**只能追加、禁重译已有条目**；合法增长须重新冻结入库 + 在 eras.json 声明新 era。实测 `temperature=0` 重译逐字一致率仅 13%~24%，重建 = 全体 AUC 平移（trust/fondness_shift A→C 就是这么掉的）。**禁止为改善等级重预热；测试永不给 `_cached_translate` 传字面量 `{}`**（曾把缓存毁到 1 条）。
2. **目录分工**：`tests/cases/` = 判分基准（4 文件，进 `_dataset_fingerprint()`）；`tests/experience/` = 体验场景（不进指纹）。**改 cases 或 narra_config.json 后必须重建基线链**：`signalmetrics` → `capability` → `capability --check`。档案不 fresh 时状态层一条 delta 都不写（症状：`state_commits` 空、trust 冻住——那是门禁在工作，不是坏了）。

### 能力与状态层
3. 能力档案是"哪些 signal 能用"的唯一权威：**只有 `role=state_shift` 且 `status=active` 才写 Actor State**。当前 td 只剩 `doubt_shift` 可写；C 级=修正项（禁止单独定事实）；R 级（`investigate`）**禁静默取反**。
4. 状态链序固定：`proposal → deadzone → per-turn clamp → range clamp → Commit`（调试字段 `{old, proposal, after_deadzone, final_delta, new}` 必须保留）。**歧义轮不 commit**（behavior_is_null/awaiting_upstream → 整轮不写——事实认定权在上游）。
5. **不许为了让测试变绿调 `grade_signal` 阈值 / 放宽死区 / 改 max_tokens**——那是"参数凑出来的绿"。当前等级（trust/fondness=C）是用户裁决接受的正式现状。
6. 改过 `laya_bridge.py` 后必须重跑 `capability`（`--check` 核对），否则档案带 `code_changed=true`。

### 实验纪律
7. **喂 Laya 一律英文**（typed-decisions 是英文 ModernBERT；中文静默失效：高置信+零准确）。玩家中文先翻英文。
8. 全部结果同号整齐 → 先做**反序配对**排除调用顺序漂移；小 Δ 判据前先**同态×3**定抖动下界；**变化量 vs 状态量并排比**（`*_shift` 是变化量，要状态量看 noul）；结论必须出自**预置判据的可执行脚本**（失败即结论）。
9. `decision_history` 轴跨检查点方向不稳 = **未触及**（≠已验证无害），体验测试都没传 history。E3 中性漂移（中性读成轻微负向）**有意不修**——要修得动模型校准。

### 代码模式
10. `decide()` 有多条返回路径（正常轮 / fail-closed 轮）——共享消费代码**一律 `.get` 不下标**（`out["engine"]` 事故，T10 钉住）。
11. 翻译 fail-closed：失败抛 `TranslationFailure` → 整轮 `status="invalid"`，**绝不回落中文**。空 content 按 `finish_reason` 区分 `length`（预算耗尽，配置问题）/ `stop`（真空回复）。
12. 架构不变式：`choice` 出分布（弱，conf 0.07~0.16）、`noul` 做覆盖（gates 强信号改写行为，带 `gated_by`）。改问题集三铁律：①instructions 反引号锚定 state 键名；②score.criteria 领域化档位描述；③choice 选项 3~5 词短标签。改完跑 `qcheck` + `langtest`。
