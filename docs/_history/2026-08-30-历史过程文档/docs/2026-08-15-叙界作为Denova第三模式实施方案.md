## 1. 目标

将 Denova 从“叙界外部依赖的另一个程序”调整为唯一桌面入口，并在现有顶层模式中加入叙界：

```text
写作模式 | 游戏模式 | 叙界
```

最终体验：用户只启动一次 `Denova.exe`，即可在三个同级模式间切换；进入叙界时不再依赖单独启动 Python 静态服务器，也不再出现“叙界套着 Denova、再返回叙界”的割裂外壳。

## 2. 首期范围

### 2.1 必须完成

- Denova 增加第三个顶层模式 `narraverse`，桌面端和移动端入口一致。
- 叙界静态前端随 Denova 打包，由 Denova 同源提供 `/narraverse/`。
- 叙界以无边框、全高的持久 iframe 嵌入 Denova 工作区。
- 在写作、游戏、叙界之间切换时，叙界 iframe 不销毁、不刷新，保留滚动位置和未提交输入。
- 叙界识别 `?embedded=denova`，隐藏重复的品牌外壳、Denova 套壳和返回栏。
- 支持 `?mode=narraverse` 直接进入叙界。
- 旧叙界快捷方式改为“启动 Denova 后进入叙界”，不再要求用户先手动运行 `Denova.exe`。
- 中英文、亮色/暗色、宽屏/窄屏均可使用。
- 明确处理旧站点 IndexedDB 数据迁移，不能让用户误以为存档丢失。

### 2.2 首期不做

- 不把叙界完整重写为 React。
- 不合并两边的业务状态仓库和数据模型。
- 不自动跨来源读取旧 IndexedDB。
- 不移除现有 `denova_bridge.py` 导出链路。
- 不实现云同步、账号系统或多人协作。
- 不重命名 Denova 现有 `interactive` 模式及其存储键。

## 3. 目标结构

```text
Denova.exe
└─ Denova Web Shell
   ├─ 写作模式（ide）
   ├─ 游戏模式（interactive）
   ├─ 叙界（narraverse）
   │  └─ /narraverse/index.html?embedded=denova
   └─ 共享入口（设置、书库、技能等）
```

原则：Denova 管顶层导航、窗口、主题和语言；叙界只管理冒险内部的侧栏、故事区、状态区与弹窗。

### 工作包 B：叙界嵌入态

**执行人：A1**  
**主要目录：** `<external-text-adventure-project>\app\`

#### B1. 启动时识别宿主

修改 `<external-text-adventure-project>\app\app.js`：

```js
const isDenovaEmbedded =
  new URLSearchParams(location.search).get('embedded') === 'denova';
document.body.dataset.host = isDenovaEmbedded ? 'denova' : 'standalone';
```

- 该状态只决定外壳和宿主通信，不改变冒险数据结构。
- standalone 模式继续可独立打开，作为过渡期兼容入口。
- embedded 模式隐藏“打开 Denova 写作台/游戏模式”等重复命令。

#### B2. 去除双重外壳

修改：

- `<external-text-adventure-project>\app\index.html`
- `<external-text-adventure-project>\app\redesign.css`
- `<external-text-adventure-project>\app\theme-neutral.css`

使用 `body[data-host="denova"]`：

- 隐藏叙界最外层重复品牌栏和现有 `denovaShell` 全屏覆盖层。
- 保留冒险侧栏、中央故事区、右侧角色状态和全部弹窗。
- 页面宽高使用 iframe 容器的 `100%`，消除外边距和双滚动条。
- 窄屏继续使用叙界自身的抽屉/响应式布局。

#### B3. 调整宿主通信方向

修改 `<external-text-adventure-project>\app\bridge.js`：

- 主流程由“叙界打开 Denova iframe”改为“叙界向 Denova 父窗口发消息”。
- 加载完成发送：

```js
window.parent.postMessage({
  source: 'narraverse',
  version: 1,
  type: 'ready'
}, location.origin);
```

- 接收父窗口 `theme-changed`、`locale-changed`。
- 请求切换模式时发送 `switch-mode`，目标只允许 `ide` 或 `interactive`。
- 校验 `event.source === window.parent` 且 `event.origin === location.origin`。
- standalone 模式可暂时保留旧 `openDenovaShell()`，但 embedded 模式绝不能显示旧套壳。
- 不直接读取或修改父页面 DOM。

#### B4. 旧数据迁移提示

当前叙界 IndexedDB 名称为 `adventureAI_db`，浏览器存储受来源隔离。切换到 Denova 同源地址后，旧 `localhost:8099` 数据无法自动读取。

在 embedded 模式首次进入且新数据库为空时展示一次迁移提示：

- 标题：`检测到新的叙界运行环境`
- 说明：旧地址中的本地存档不会自动迁移。
- 主按钮：`导入旧叙界备份`，复用现有 `importAllData()`。
- 次按钮：`暂不导入`。
- 提醒用户在旧叙界中先执行现有 `exportAllData()`。
- “暂不导入”只关闭提示，不得伪造迁移成功状态。

首期禁止宣称可以自动迁移跨来源 IndexedDB。

#### B5. B 包静态验证

- standalone 打开时现有功能不变。
- embedded 打开时无重复 Denova 外壳和重复切换命令。
- 父窗口主题、语言和模式消息能正常处理。
- 迁移提示只在符合条件时出现，导入继续调用现有逻辑。

## 5. 消息协议 v1

首期只使用以下信封：

```ts
type HostMessage = {
  source: 'denova' | 'narraverse'
  version: 1
  type: 'ready' | 'switch-mode' | 'theme-changed' | 'locale-changed'
  payload?: Record<string, unknown>
}
```

允许消息：

| 方向 | type | payload |
|---|---|---|
| 叙界 → Denova | `ready` | 可省略 |
| 叙界 → Denova | `switch-mode` | `{ mode: 'ide' | 'interactive' }` |
| Denova → 叙界 | `theme-changed` | `{ theme: 'light' | 'dark' }` |
| Denova → 叙界 | `locale-changed` | `{ locale: 'zh-CN' | 'en-US' }` |

首期不要加入保存、角色卡、世界书和故事正文同步消息；后续按真实需求单独版本化。
