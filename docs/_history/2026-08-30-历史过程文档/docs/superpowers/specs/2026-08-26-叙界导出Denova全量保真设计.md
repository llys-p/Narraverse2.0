# 叙界导出 Denova 全量保真与低成本翻译设计

> 日期：2026-08-26  
> 状态：用户已批准规格；2026-08-26 09:32 已完成核心实施、生产构建、运行态部署、HY-MT 下载注册与最终验收（本机缺少 Go 工具链，未执行无源码改动范围的 Go 定向测试）  
> 范围：当前叙界冒险的手动“导出 Denova”流程

## 1. 目标

把当前叙界冒险完整、可核验、可继续编辑地迁移到 Denova，使 Denova 能识别：

- 当前主线的完整原始对话；
- 当前冒险已挂载的完整角色卡；
- 当前冒险已挂载的完整世界设定卡/设定书；
- 角色卡中的扩展字段、示例对话、备用开场和作者约束；
- 原文主要为英文时生成的中文译文；
- 可选的小说化章节，而不把 AI 摘要或 AI 改写当作唯一真源。

基础搬运和英中翻译不得消耗用户的昂贵云端模型 Token。导入必须给出可复核的数量、字段、字节数和失败明细；存在缺失或截断时不得显示为完整成功。

## 2. 已确认的产品决策

1. “前情摘要”不再承担迁移真源职责，只可作为可删除的导航材料。
2. 对话先完整落地；小说是可重复生成的衍生品，不是导出前置条件。
3. 英中翻译使用本地专业翻译模型，首选 `HY-MT1.5-1.8B` 的 GGUF 量化版本。
4. 角色卡和设定书优先使用确定性字段映射；大模型不参与基础字段搬运。
5. NSFW 内容不净化、不省略；通过本地推理、术语表、逐字段翻译和失败重试保证一致性。
6. 叙界自己的轻量导演提示不导出；Denova 后台导演保留，但叙界导入的游戏默认“仅手动”。
7. 本次只处理当前冒险及其当前挂载素材，不批量迁移所有冒险或整个知识库。

## 3. 非目标

- 不改变现有自动同步的节流和有限载荷策略；本设计只替换显式手动全量导出。
- 不自动删除用户现有的 `qwen3.6:latest`、Llama 或其他 Ollama 模型。
- 不在未确认的情况下下载数 GB 模型。
- 不默认把废弃分支混入当前主线正史。
- 不用一份巨型 Markdown 同时承载全部对话、角色、世界观和提示词。
- 不允许重新导出静默覆盖用户在 Denova 中手工修改的资料。

## 4. 现状问题与事实依据

### 4.1 角色卡实际只导出了截断版

`tools/gen_local_library_v2.py` 在建立本地加载库时会截断内容，并附加“内容已截断，完整版见 knowledge-base 原文件”。当前 `app/app.js` 导出的是冒险对象中已截断的卡片，`tools/denova_bridge.py` 没有回到 `knowledge-base` 读取原件，因此 Denova 当前没有收到完整角色卡。

### 4.2 当前导出遗漏角色卡扩展字段

叙界已能归一化 `appearance`、`relationship`、`notes`、`creator_notes`、`alternate_greetings`、`character_note`、`note_depth`、`system_prompt`、`post_history_instructions` 等字段，但当前导出只发送姓名、简介、性格、场景、开场白和标签。

### 4.3 当前摘要和小说生成都没有覆盖完整历史

- 导出摘要只读取最近 8 条 AI 消息，并把原文限制在 6000 字符。
- 小说生成只读取当前 `conversationHistory`；压缩前历史只存在于快照时不会进入生成。
- 单章生成输入还会截到 8000 字符。
- 没有预先生成的小说章节会在导出时被过滤掉。

### 4.4 快照不是永久完整档案

上下文压缩前会建立完整快照，但快照总数限制为 24，超限后会优先清理自动快照。因此现存旧冒险可以尽力从快照恢复，但已被清理的最早对话无法凭空重建。

### 4.5 当前桥接存在全局截断

`tools/denova_bridge.py` 每本最多解析 200 条、全局最多写入 500 条。当前角色卡全部设为 `resident`，会让 Denova 每轮上下文被大量角色正文占满。

### 4.6 本机 Qwen 3.6 不适合承担批量任务

本机 `qwen3.6:latest` 是 36B MoE、多模态、Q4_K_M，磁盘体积约 23 GB。实测日志显示模型缓冲区约占 CPU 17.6 GiB、GPU 4.38 GiB，服务启动约 594 秒，随后一次聊天请求等待 13 分 35 秒后返回 HTTP 500。它不接入本次翻译或常驻整理流程。

## 5. 总体架构

```text
叙界当前冒险
  ├─ 当前对话 + 压缩快照 + 分支记录
  └─ 当前挂载素材的来源引用
                 │
                 ▼
        全量导出清单与回源解析
  ┌──────────────┼─────────────────┐
  ▼              ▼                 ▼
原始对话档案   完整英文原件      当前状态/元数据
  │              │
  │              ▼
  │       本地 HY-MT 逐字段翻译
  │              │
  └───────┬──────┘
          ▼
   Denova 工程原子写入
  ├─ .narraverse/source/ 原始真源与英文备份
  ├─ chapters/ 可读剧情实录或小说章节
  ├─ .denova/lore/items.json 原生资料条目
  ├─ setting/ 当前状态与写作说明
  └─ .narraverse/import-manifest.json 验收清单
```

## 6. 数据真源与回源规则

### 6.1 新挂载素材

角色卡和设定书挂载到冒险时新增不可见来源信息：

```json
{
  "source_ref": {
    "kind": "character_card|lorebook",
    "relative_path": "角色卡/example.json",
    "source_id": "稳定来源 ID",
    "source_hash": "sha256"
  }
}
```

界面仍可显示短预览，但手动导出只把预览用于展示，实际内容必须通过 `source_ref` 回到 `knowledge-base` 原文件读取。

### 6.2 已有旧冒险

旧对象没有 `source_ref` 时按以下顺序匹配：

1. 原文件名或已保存的标题；
2. 角色卡内部 `name`；
3. 标准化后的字段指纹；
4. 唯一候选的内容相似度。

匹配为 0 个或多个候选时不静默猜测。该素材标记为 `unresolved`，导出预检展示原因；用户可以跳过、手工选原件或以现存截断数据导出，但最后一种必须标记为“不完整”。

### 6.3 原件保留

每个已解析原件原样复制到 Denova 工程的 `.narraverse/source/` 下，并在清单中记录原始路径、哈希、字节数和目标资料 ID。中文资料库正文不是唯一副本。

## 7. 完整对话设计

### 7.1 现有冒险恢复

按时间和消息内容指纹合并：

- 当前 `conversationHistory`；
- `kind=compress` 的压缩前快照；
- 手动/线路快照；
- 当前主线对应的分支前缀。

去重以稳定消息 ID 为优先；旧数据没有 ID 时使用 `role + content + 邻接消息 + 时间信息` 的组合指纹。恢复结果分为：

- `complete`：可证明连续；
- `best_effort`：存在历史压缩但无法证明最早段完整；
- `incomplete`：发现明确缺口。

### 7.2 未来冒险永久档案

在 IndexedDB 中为每个冒险维护独立、分块的追加式对话日志，不把它注入 LLM 上下文，也不放进自动同步载荷。日志记录消息创建、编辑、回溯和分支归属。上下文压缩只改变工作上下文，不删除档案。

### 7.3 Denova 输出

- `.narraverse/source/conversation.jsonl`：主线机器可读原始消息；保留用户与助手角色、可见正文、时间和消息 ID，不导出 API 密钥、隐藏思考内容或上下文压缩生成的系统摘要。
- `.narraverse/source/runtime-instructions.md`：单独保存用户明确配置的自定义提示与角色约束；运行时自动生成的巨大系统提示只记录哈希，不重复写入。
- `对话全文.md`：完整、可人工检查的主线实录。
- `chapters/剧情实录-001.md` 等：按消息边界和目标字节数机械分卷，不概括、不重写、不在半条消息中切断。
- `.narraverse/source/branches/<branch-id>.jsonl`：废弃或旁支对话单独保存，不混入当前正史。

Denova 的 CREATOR 说明必须明确：资料库是稳定设定，剧情实录是已发生事实，导演计划是未来规划，三者不得混写。

### 7.4 小说化

导出后提供“根据剧情实录生成小说章节”的可选动作：

- 每个实录分卷都必须被消费，不能使用固定字符串截断；
- 按章节保存检查点，可暂停、重试和继续；
- 生成章节记录来源分卷 ID；
- 小说章节失败不影响原始导入成功；
- AI 小说不得覆盖 `.narraverse/source/` 或剧情实录。

## 8. 角色卡与设定书映射

### 8.1 角色卡拆分

一张完整角色卡按语义拆为最多三类 Denova 原生资料：

1. `角色名 · 核心设定`
   - 姓名、别名、身份、外貌、性格、关系、能力、稳定背景；
   - 类型 `character`；主角/玩家绑定角色可为 `resident`，其余默认 `auto`。
2. `角色名 · 演绎参考`
   - 说话风格、示例对话、首条消息、备用开场；
   - 类型 `character`，默认 `auto` 或 `manual`。
3. `角色名 · 创作者约束`
   - `character_note`、`note_depth`、`system_prompt`、`post_history_instructions`、`creator_notes`；
   - 默认 `manual`，避免元指令无条件污染每轮游戏上下文。

空分组不创建。所有非空原字段必须出现在某个资料条目或英文原件侧车中，清单记录字段级去向。

### 8.2 设定书拆分

每个原始 world-info/lorebook entry 生成一个资料条目，不再使用每本 200 条或总计 500 条上限。保留名称、关键词、禁用状态、顺序、来源、标签和完整正文。

加载策略默认：

- 当前核心规则、玩家身份：`resident`；
- 普通角色、地点、势力、物品和世界知识：`auto`；
- 作者说明、正则脚本、仅供参考的大段素材：`manual` 或禁用保存。

不得把全部角色设为常驻。Denova 的 64 KiB 名称目录和单次读取限制是模型读取分页规则，不是存储截断理由。

“全部导入”表示所有条目均完整存储、可检索、可分页读取，不表示每一轮都把全部正文塞进模型上下文。导入清单和 CREATOR 会提示 Agent 使用资料库检索工具；核心资料常驻，其余依靠名称、简介、关键词和类型按需命中。这样才能同时满足完整性和可用上下文长度。

### 8.3 模板与扩展内容

- 英文原件中 `{{char}}`、`{{user}}` 原样保留；
- 中文资料条目中 `{{char}}` 替换为实际角色名，`{{user}}` 替换为玩家名，未知时使用“玩家”；
- HTML 标签、Markdown 结构、URL、正则、代码块和未知模板变量先占位保护，翻译后原样恢复；
- 可执行扩展、脚本和正则默认禁用保存，不直接进入模型常驻上下文。

## 9. 本地英中翻译

### 9.1 模型

首选 `HY-MT1.5-1.8B-GGUF` 的适当量化版本，由 Ollama 或 llama.cpp 暴露本地接口。使用前预检：

- Ollama 是否在线；
- 模型是否存在；
- 可用显存和模型体积是否合理；
- 一条短文本健康检查是否在超时内返回。

模型缺失时只展示安装选项和预计下载量，必须由用户确认。不得自动回退到收费 API。

### 9.2 翻译单位

按角色卡字段或设定条目正文翻译，不把整本设定书塞进一个请求。单批按段落边界控制长度，并携带：

- 源语言 `en`、目标语言 `zh`；
- 角色名和作品上下文；
- 当前术语表；
- “忠实翻译、不总结、不净化、不续写”的固定约束；
- 受保护占位符列表。

### 9.3 NSFW 术语表

项目提供可编辑的英中术语表，支持：

- 固定译名；
- 人名、称谓和代词一致性；
- 身体部位、行为和性癖术语；
- 禁止翻译的专名；
- 单冒险覆盖全局词条。

术语表只决定翻译一致性，不承担内容审查。

### 9.4 缓存、恢复和校验

缓存键由 `源文本哈希 + 模型 ID + 语言方向 + 术语表版本` 组成。中断后只重跑未完成字段。每个结果至少检查：

- 非空输入没有变成空输出；
- 占位符数量与原文一致；
- 未出现模型解释、拒绝话术或 Markdown 包装污染；
- 原文专名和术语表要求得到保留；
- 输出没有异常缩短或重复。

失败字段保留英文原文并列入报告，不伪装为成功。

## 10. Denova 导演简化

### 10.1 叙界侧

退役叙界自己的轻量导演台：主界面不再展示该面板，`buildDirectorPromptBlock` 不再注入普通/酒馆模式，`EVENT/CHECK` 导演协议不再作为叙界运行要求，也不写入 Denova 导出。已有冒险对象中的 `director` 数据保留用于向后兼容和回滚，但不再参与新回合生成。

### 10.2 Denova 侧

Denova 已支持：

- `on_demand`：首回合建计划，重大变化时更新；
- `manual`：从不自动调用，只能手工运行；
- `interval`：每 X 回合调用。

从带有叙界导入清单的工程新建 Denova 游戏故事时，默认策略为 `manual`。导演后台入口折叠进高级/幕后区域，主游戏界面不持续占位；需要复杂阴谋线、长期伏笔或卡剧情时可手动运行。普通 Denova 工程的默认值和已有 Denova 故事设置均不改变。

## 11. 重复导出、冲突与原子性

### 11.1 稳定 ID

资料 ID 由 `叙界同步 ID + 来源 ID + 语义分组` 稳定生成。重复导出执行 upsert，不产生重复角色。

### 11.2 Denova 手工编辑保护

清单保存上次写入的内容哈希：

- Denova 条目仍等于上次导入版本：允许自动更新；
- Denova 条目已被手工修改：不覆盖，生成冲突记录并保留新旧两份；
- 用户明确选择覆盖或合并后才更新基线。

### 11.3 原子提交

导出先写临时目录并完成清单校验，再原子替换受管文件。替换前备份到 `.narraverse/backups/<timestamp>/`。取消或中途失败不得留下半套资料库。

## 12. 导出交互

手动“导出 Denova”调整为六步状态：

1. 清点当前冒险与挂载素材；
2. 回源解析完整原件；
3. 恢复并分卷完整对话；
4. 本地翻译英文资料；
5. 原子写入 Denova；
6. 哈希和数量验收。

预检界面显示：

- 对话恢复等级；
- 找到/未找到的完整原件；
- 本地翻译模型状态；
- 预计条目数和待翻译字段数；
- 目标 Denova 工程；
- 导演模式，默认“仅手动”。

翻译步骤允许暂停和续跑。原始资料已经完整落地时，翻译失败不回滚原件，但最终状态为“导入完成，翻译有失败”，不能显示为全绿成功。

## 13. 导入清单与验收报告

`.narraverse/import-manifest.json` 至少包含：

- 格式版本、导出时间、冒险 ID 和同步 ID；
- 主线消息总数、分支消息总数、恢复等级；
- 角色卡数、原字段数、非空字段数及每字段去向；
- 设定书数、条目数、禁用条目数；
- 原文件路径、源哈希、译文哈希、目标资料 ID；
- 翻译模型、量化版本、术语表版本；
- 新增、更新、跳过、冲突、失败和截断计数；
- 小说章节和来源实录分卷的映射。

用户看到的报告示例：

```text

旁支对话：42 / 42（单独归档）
角色卡：12 / 12
角色非空字段：184 / 184
世界书条目：247 / 247
翻译完成：419

冲突：0
截断：0
```

## 14. 错误处理

- 原件找不到：阻止“完整成功”，允许用户定位原件或明确接受不完整导出。
- Ollama 不在线：原文可先导出，译文保持待处理；不调用付费模型。
- 模型超时：保存已完成缓存，卸载模型后可继续。
- NSFW 字段拒绝：缩小分段、使用专业翻译提示重试；仍失败则保留英文并报告。
- Denova 正在编辑同一条目：遵守修订冲突，不强写。
- 磁盘不足：在写临时目录前检查预计空间，提前失败。
- 用户取消：停止新请求，保留翻译缓存，清理临时提交目录。

## 15. 验收标准

### 15.1 完整性

- 没有任何输出包含“内容已截断，完整版见 knowledge-base 原文件”。
- 人工抽取至少一张长角色卡，原件所有非空字段均可在清单中定位。
- 超过 200 条的单本设定书和总计超过 500 条的素材能完整导入。
- 对话压缩后继续游玩，再导出仍能从永久档案生成完整实录。
- 分支内容不会混入当前主线，但能在单独档案中找到。

### 15.2 翻译

- 主要英文角色卡可在不配置云端 API 的情况下完成中文翻译。
- NSFW 测试词条不被星号替换、概括或删除。
- `{{char}}`、`{{user}}`、代码块、URL 和正则不被错误破坏。
- 中断后重新开始不会重复翻译已缓存字段。
- 本机 8GB 显存环境不加载 23GB 的 `qwen3.6:latest`。

### 15.3 Denova 使用

- 资料库中角色、世界、地点、势力、规则、物品可分别检索。
- 非核心角色默认按需加载，常驻内容不会因全部角色卡而无界增长。
- 重复导出不产生重复条目，不覆盖手工编辑。
- 新导入游戏不会自动调用后台导演；用户可从高级入口手动运行。
- 不生成小说也能在 Denova 找到全部实录；生成小说失败不会损坏实录。

### 15.4 回归

- 旧的自动同步仍使用原有有界载荷，不因全量手动导出而变慢。
- 未使用全量导出的旧冒险和旧 Denova 工程保持不变。
- 叙界正常对话、上下文压缩、快照、分支和手动存档行为不退化。

## 16. 建议实施顺序

1. 先建立来源引用、完整对话档案和导出清单，解决“数据是否完整”的真源问题。
2. 重写桥接的完整素材解析、稳定 ID、冲突保护和原子提交。
3. 接入本地 HY-MT、术语表、缓存和翻译校验。
4. 调整 Denova 资料库映射、加载策略和导入报告。
5. 移除跨系统重复导演提示，并把导入故事设为仅手动导演。
6. 最后增加可选小说化入口；它不能阻塞前五步交付。

## 17. 与既有设计的关系

本设计补充并局部修正 `docs/2026-08-15-denova-entry-and-future-sync-design.md`：

- 既有自动同步继续保持有界、轻量；
- 显式“导出 Denova”升级为当前冒险的全量保真迁移；
- 旧设计中“conversation history remains local”只适用于自动同步，不再限制用户主动全量导出；
- 原有旧冒险不自动迁移原则不变，只有用户主动执行全量导出时才处理。
