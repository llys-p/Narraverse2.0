# 叙界总资料库设计

日期：2026-08-27  
状态：用户已批准设计，待规格复核  
范围：现有角色卡与设定书治理、中文总库、可选在线润色、跨冒险选择性加载

## 1. 目标

建立一个独立、干净、可持续补充的 Denova 总资料库。英文原件永久保留，本地 HY-MT 初译直接作为可用中文版本进入总库；用户不满意时，再让 Denova 在线强模型根据明确的原文映射进行润色。

其他冒险不读取整个总库，而是按需选择角色和设定，复制为带来源与版本信息的受管快照。每个冒险中的人物记忆、关系、成长和状态完全独立，不反写总库，也不传播到其他冒险。

## 2. 工程位置与边界

总库工程目录固定为：

```text
<project-root>\denova\.denova\projects\narraverse-master-library\
```

Denova 书架显示名称为“叙界总资料库”。英文目录 ID 避免中文路径影响脚本和外部工具。

该工程只保存整理后的角色模板与世界设定，不承载故事、游戏对话或冒险运行状态。`knowledge-base/` 继续作为未整理原始素材入口；`app/` 和普通冒险工程不存放总库真源。

## 3. 开始前备份

首次整理前创建不可变备份：

```text
<project-root>\.workbuddy\backups\master-library-<YYYYMMDD-HHMMSS>\
```

备份范围包括：

- `knowledge-base/角色卡/`
- `knowledge-base/世界观设定/`
- 相关元数据和生成索引
- `denova/.denova/books.json`
- 已存在的总库工程（若有）

备份后先生成文件清单、字节数和 SHA-256；未完成校验前不得开始迁移。

## 4. 总库目录结构

```text
narraverse-master-library\
├─ .denova\
│  └─ lore\items.json
├─ .narraverse\
│  ├─ source\originals\
│  ├─ master-library-manifest.json
│  └─ backups\
├─ 资料整理\
│  ├─ 润色任务清单.md
│  └─ <source_id>\
│     ├─ 原文.json
│     ├─ HY-MT初译.json
│     ├─ 润色结果.json
│     └─ 校验报告.json
├─ CREATOR.md
└─ setting\world.md
```

`.narraverse/source/originals/` 保存原始 PNG/JSON 二进制副本。PNG 角色卡同时在 `资料整理/<source_id>/原文.json` 保存解码后的完整可读字段，供翻译、验收和在线模型读取。

## 5. 清点、去重与版本

每个素材获得稳定 `source_id`。来源记录至少包含：原始相对路径、文件名、内部名称、类型、SHA-256、字节数、导入时间和格式版本。

去重规则：

- SHA-256 完全一致：自动判定重复，不再次导入。
- 名称相同、哈希不同：全部保留为不同版本，标记版本冲突，不按名称覆盖。
- 名称和哈希均不同：作为新素材。
- 更新同一来源时，受管且未手改的条目可以更新；已手改条目保留，并生成冲突候选。

角色卡与设定书均以原始素材为版本边界。设定书内部仍是一条源 entry 对应一条 LoreItem，不把整本书压成单条。

## 6. 翻译与质量门槛

### 6.1 试验批

正式批量整理前先选择三份代表素材：

1. 对白与人物口吻丰富的角色卡。
2. 条件、规则和数字密集的设定书。
3. 包含明确 NSFW 术语的素材。

试验批检查遗漏、否定句、数字、专名、人物语气、露骨程度、占位符和结构完整性。任一类型出现系统性失真时，暂停该类型批量处理并调整提示词或分块规则。

### 6.2 HY-MT 初译

- 名称使用中文化/音译模式。
- 角色描述、性格、场景、对白示例、开场白和作者约束分字段翻译。
- 设定书按 entry 和段落翻译，不跨条目总结。
- 固定要求忠实、不总结、不净化、不续写、不补设定。
- 保护 `{{char}}`、`{{user}}`、URL、Markdown、HTML、代码块、正则和脚本。
- 脚本、正则和机器字段默认不翻译，并以 `manual` 或禁用状态保存。
- 中文关键词保留英文别名，正文只保存中文工作版，避免中英文正文同时进入上下文。

HY-MT 初译通过结构校验后直接进入 `.denova/lore/items.json`，不要求逐条人工确认。失败字段的英文只保留在整理包和报告中；缺少必需译文字段的角色条目或设定 entry 不得启用，也不能被其他冒险选择加载，直到补译成功。失败结果不能显示为完整成功。

### 6.3 可选在线润色

在线润色不属于首轮入库的阻塞步骤。平台只负责生成清晰的文件对应关系：

- `source_id`
- 英文原文路径
- HY-MT 初译路径
- 润色结果目标路径
- 原文字段到译文字段的精确映射
- 原文与初译 SHA-256
- 禁止改动的占位符和机器字段

`资料整理/润色任务清单.md` 供 Denova AI 直接读取。在线模型不得靠文件名猜测来源，也不得覆盖英文原件；其输出写入 `润色结果.json`。后续采用润色结果时继续执行字段、哈希和冲突校验。

翻译状态为：`untranslated → hy_mt_active → polish_candidate → polished_active`。`hy_mt_active` 表示初译已经是总库当前可用版本；在线模型写出文件后进入 `polish_candidate`，只有通过字段、哈希和冲突校验并实际替换总库工作版后才进入 `polished_active`。

## 7. 总库资料分类与加载策略

- 玩家绑定角色和确需每轮遵守的核心规则才可设为 `resident`。
- 普通角色、地点、组织和世界知识默认 `auto`。
- 作者约束、脚本、正则和工具说明默认 `manual` 或禁用。
- 关键词保存中文主词和英文别名，支持中文剧情与英文专名同时命中。
- 成人内容保留明确标记和分类，不净化，也不在未启用成人素材时误显示。

## 8. 向其他冒险加载受管快照

普通冒险的“加载资料”增加三个来源：

```text
总资料库 / 叙界原始库 / 本地上传
```

从总库勾选条目时，复制中文工作版到当前冒险，并记录：

- `master_item_id`
- `master_version_hash`
- `master_source_id`
- 加载时间
- 当前冒险受管内容哈希
- 本地修改状态

总库后续更新只显示“有新版”，不自动改动正在进行的冒险。未被当前冒险修改的受管字段可由用户确认更新；已修改字段保留，并生成冲突副本。

从冒险移除受管快照不删除总库条目。普通冒险不能反向修改或污染总库。

## 9. 冒险中途加载

冒险进行中可以继续加载角色和设定：

- 新设定从下一轮开始参与关键词检索。
- 新角色默认“加入世界”，不会立刻进入当前场景。
- `first_mes` 不自动插入既有对话。
- 用户可另行选择“加入当前场景”，让角色从下一轮自然登场。
- 加载操作不修改过去的对话、人物关系和剧情记录。

## 10. 角色模板、冒险实例与状态隔离

总库角色只保存基准模板：核心身份、基础外貌、初始性格、说话风格、原始背景、固定能力与边界。

每个冒险加载后创建独立角色实例：

```text
总库角色模板
├─ 冒险 A：本地设定差异 + 独立经历状态
└─ 冒险 B：本地设定差异 + 独立经历状态
```

实例记录 `master_character_id`、`master_version_hash` 和本地覆盖；记忆、关系、成长、伤势、阵营、服装、位置等运行状态继续保存于当前冒险状态系统，不写入总库 LoreItem。

默认所有冒险的记忆和成长完全独立。只有用户明确选择“继承某次冒险版本”时，才复制该实例作为另一个冒险的起点。冒险实例只有在用户主动执行“另存为总库变体”时，才能成为新的总库版本。

## 11. 后续新增素材

新增素材必须在“叙界总资料库”工程内操作：

```text
新增英文卡片
→ 加载资料
→ 选择叙界知识库或本地上传
→ 预览、去重和版本判断
→ 归档英文原件
→ HY-MT 完整翻译
→ 写入中文总库
→ 其他冒险按需选择加载
```

复用现有角色卡解析、设定书逐 entry 拆分、来源引用、稳定 ID、完整原件归档和手改冲突保护。总库模式与普通冒险的区别是：新导入素材默认翻译全部可翻译正文，而不只翻译名称和简介。

## 12. 原子性、恢复与报告

- 每个原始素材是一个独立事务；失败时回滚该素材，不回滚已完成素材。
- 写入原件、清单和 LoreItem 前创建恢复点并使用原子替换。
- 翻译按字段保存检查点，暂停或崩溃后只继续未完成字段。
- 报告区分创建、更新、重复、冲突、翻译失败、截断和不支持字段。
- 任何缺失、截断、冲突或翻译失败都不能显示为全绿成功。
- 原始英文文件和历史备份不得由整理、翻译或润色流程自动删除。

## 13. 实施顺序

1. 备份、清单和哈希校验。
2. 新建并注册总库工程。
3. 扩展总库 manifest 与原件/初译目录。
4. 完成三份试验批和质量报告。
5. 实现总库模式的完整翻译入库。
6. 分批整理角色卡与设定书。
7. 在普通冒险增加“总资料库”来源和受管快照。
8. 增加版本提示、冲突处理与冒险中途加载动作。
9. 生成在线润色任务映射。
10. 完整回归、真实素材抽检和部署。

## 14. 验收标准

- 备份清单中的文件数、字节数和 SHA-256 可复核。
- 完全重复素材不重复入库；同名不同内容不被覆盖。
- 三份试验批无结构损坏、占位符损坏、净化、总结或明显遗漏。
- 英文原件、HY-MT 初译、润色候选和最终 LoreItem 可由 `source_id` 双向定位。
- 总库正文只注入中文工作版；英文原件不进入游戏上下文。
- 设定书超过 200 条仍逐条完整导入。
- 普通冒险只加载用户选中的条目，不全库常驻。
- 总库更新不静默覆盖冒险快照或本地修改。
- 冒险 A 的记忆、关系和成长不会出现在冒险 B。
- 冒险中途加载角色不会自动插入 `first_mes` 或改写过去对话。
- 暂停、续跑、失败、截断和冲突状态均可见且可恢复。

## 15. 范围外

- 不让所有冒险实时引用总库最新版。
- 不把整个总库设为 resident。
- 不覆盖或删除英文原件。
- 不自动把冒险经历反写总库。
- 不自动把冒险角色实例升级为总库变体。
- 不要求在线润色完成后才能使用总库。
- 不批量修改当前已有冒险的资料和运行状态。
