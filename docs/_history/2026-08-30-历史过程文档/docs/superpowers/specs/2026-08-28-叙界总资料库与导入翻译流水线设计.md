# 叙界总资料库与导入翻译流水线设计（批准规格）

日期：2026-08-28  
状态：架构方向已获用户确认；本文件是现行计划规格，尚未实施总库迁移或业务代码改造  
历史基线：`2026-08-27-narraverse-master-library-design-v2.md`、`2026-08-26-denova-background-translation-and-material-library-design.md`

## 1. 已批准结论

普通冒险导入新素材时，默认执行 `master_managed` 流程：先将原文件纳入叙界总资料库，完成解析、清洗、翻译和校验，再从总库当前有效版本创建该冒险的独立实例。用户在界面上仍可一键完成“导入并使用”，但后端顺序不得绕过总库。

高级模式保留 `unmanaged_direct`：素材可以临时直接进入当前冒险，但必须明确标记为不受管，不更新总库、不能跨冒险复用，也不自动获得总库更新；以后可由用户主动“提升到总库”。

总架构固定为四层：

1. 原文件层：永久保留、不可覆盖的证据。
2. 清洗翻译层：解析结果、HY-MT 初译和 Agent 润色候选的版本链。
3. 总资料库层：跨冒险复用的标准条目与当前有效版本。
4. 冒险实例层：某个冒险实际加载的独立副本与运行状态。

系统同时区分三种“真相”：原文件是来源真相；总库 active 版本是标准真相；冒险实例是当前冒险真相。清洗翻译层是可追溯的派生版本，不是另一套互相竞争的真源。

## 2. 目标、边界与数据流

目标是让同一张角色卡或同一本设定书只清洗、翻译一次，之后可被多个冒险复用，同时保留原件、每次翻译结果和每个冒险自己的改动。

```text
新素材
  ↓
不可变原件归档
  ↓
结构化解析与确定性清洗
  ↓
按字段建立 HY-MT 初译任务
  ↓
占位符 / 结构 / 长度 / 格式校验
  ↓
通过校验的中文工作版
  ├─→ 总库 active 版本 → 运行时投影 → 冒险 instance
  └─→ 选择性 Denova Agent 润色候选 → 用户激活 → 新 active 版本
```

总库只保存可复用的角色模板与世界知识，不保存某次冒险的记忆、关系、伤势、位置、成长、剧情经历或聊天记录。冒险状态不得自动反向污染总库。

## 3. 工程位置与目录

总库工程固定为：

```text
<project-root>\denova\.denova\projects\narraverse-master-library\
```

Denova 显示名称为“叙界总资料库”。建议持久化结构：

```text
narraverse-master-library\
├─ .denova\
│  └─ lore\items.json                         # Denova 运行时投影，不是总库真源
├─ .narraverse\
│  ├─ master-library-manifest.json             # 唯一映射索引
│  ├─ source\
│  │  ├─ originals\<source_id>\<sha256>\...  # 不可变原件
│  │  └─ normalized\<source_id>\<sha256>\parsed.json
│  ├─ master\items\<master_item_id>.json      # 总库规范条目
│  ├─ translations\<translation_version_id>.json
│  ├─ snapshots\<adventure_id>\<instance_id>.json
│  ├─ transactions\
│  ├─ audit-log.jsonl
│  └─ backups\
├─ 资料整理\                                    # 系统生成的人类可读视图，不作为真源
├─ CREATOR.md
└─ setting\world.md
```

首次迁移前仍需创建带 SHA-256 清单的不可变备份。备份校验不完整时禁止迁移。

## 4. 四级 ID 与版本契约

### 4.1 `source_id`：来源谱系

`source_id` 表示一份原始素材的来源谱系，而不是内容哈希或拆分后的条目。一本世界书只有一个 `source_id`，其中每条 entry 另有自己的 `master_item_id`。

- 有稳定外部来源时，使用 `uuid5(NARRAVERSE_SOURCE_NAMESPACE, canonical_origin_key)` 确定性生成；来源键由来源类型、稳定外部 ID/知识库相对路径和内部卡片 ID 规范化组成。
- 没有稳定来源锚点的首次用户上传，在完成 SHA-256 去重后分配一次性 UUID，并把它持久化为后续关联依据；不得用文件名充当谱系身份。
- 用户上传文件如果与已有原件 SHA-256 完全一致，视为同内容重复，只登记别名或导入事件。
- 同名但 SHA-256 不同，且没有稳定外部来源或用户明确关联时，必须新建 `source_id`。
- 只有稳定外部身份或用户明确指定“这是旧素材的新修订”，才沿用原 `source_id` 并新增 source revision。
- 文件改名、移动或翻译不得改变已有 `source_id`。

### 4.2 `master_item_id`：总库条目

`master_item_id` 表示一个可独立加载的规范条目，生成契约为：

```text
uuid5(NARRAVERSE_ITEM_NAMESPACE,
      source_id + "\0" + source_entry_identity + "\0" + record_kind)
```

其中 `record_kind` 是稳定的结构类型，例如 `character_template`、`worldbook_entry`；`semantic_type` 是可修改的语义分类，例如 `character`、`location`、`faction`、`rule`。ID 只能使用 `record_kind`，绝不能依赖 AI 判断或以后可能修改的 `semantic_type`。

### 4.3 `translation_version_id`：翻译或润色结果

每次持久化的 HY-MT 初译、人工修订或 Agent 润色结果都生成独立的 `translation_version_id`，并记录其父版本、模型、提示词/校验器版本、字段路径、输入 revision 和校验报告。

`translation_version_id` 是首次成功持久化时分配的不可变 UUID。相同输入 revision、字段路径、语言、翻译器/提示词/校验器版本和结果哈希再次提交时复用既有版本，不制造重复记录。

翻译队列的 `job_id` 只是一次执行任务，`job_id != translation_version_id`。失败且未产生可用结果的任务可以没有翻译版本；重试也可以产生新的任务和新的版本。

### 4.4 `instance_id`：冒险实例

每次把总库条目加载到某个冒险时生成新的 UUID `instance_id`。它记录 `master_item_id`、加载时的 active revision、字段快照和本地覆盖。不同冒险即使加载同一总库条目，也必须拥有不同实例和完全隔离的运行状态。

### 4.5 revision 与通用版本字段

内容 SHA-256/source revision 与上述四个业务 ID 分开保存。核心对象至少包含：

```json
{
  "schema_version": 3,
  "data_version": 1,
  "revision": "sha256:<canonical-json-hash>",
  "updated_at": "2026-08-28T07:29:00+08:00"
}
```

ID 一旦进入 manifest 或冒险快照，不因改名、翻译、重新排序、语义重分类或 active 版本切换而改变。

## 5. 条目身份识别与去重

世界书 entry 的 `source_entry_identity` 按以下优先级确定：

1. 原格式提供且稳定的 entry ID；数值 `0` 也是有效 ID。
2. 此来源此前已持久化的 synthetic ID。
3. 对规范化关键字段生成的内容指纹。
4. 低置信度候选匹配。

数组位置 `entry-N` 只能用于本次解析和错误定位，不得成为永久身份。低置信度时默认新建条目并提示“可能重复”，不得静默合并。

去重规则：

- 相同 SHA-256：内容幂等，不重复保存原件、条目或翻译版本。
- 同名不同 SHA-256：不得按名称覆盖。
- 可证明同一来源谱系：新增 source revision，保留历史。
- entry 变化但稳定身份相同：更新同一 `master_item_id` 的数据版本。
- 无法证明身份相同：新建条目并记录待人工关联。

## 6. 总库规范模型

### 6.1 SourceRecord

至少保存 `source_id`、来源类型、原始文件名、格式、相对路径、SHA-256、字节数、来源 revision、导入时间、别名、父 revision 和完整性状态。所有路径必须是总库工程内相对路径。

### 6.2 MasterItem

至少保存：

- `master_item_id`、`source_id`、`source_entry_identity`；
- 稳定 `record_kind` 与可修改 `semantic_type`；
- 原始结构化内容及 revision；
- `active_translation_versions`：`field_path → translation_version_id` 的映射，以及由这些字段组合计算的 `active_working_revision`；
- `source_semantics` 与 `runtime_semantics`；
- 生命周期、身份置信度、可能重复项和版本历史。

`source_semantics` 保留原格式的全部可识别含义；`runtime_semantics` 只保存 Denova 当前实际执行的关键词、加载模式、触发条件和优先级。两者不得混写，否则当前运行时不支持的原字段会在导入时永久丢失。

### 6.3 CharacterTemplate

角色卡在总库中的规范形态是一个结构化 `CharacterTemplate`，而不是提前压成一个巨型 Markdown LoreItem。至少保留：

- 名称、description、personality、scenario；
- `first_mes` 与全部 `alternate_greetings`；
- `mes_example`；
- `system_prompt`、`post_history_instructions`；
- `creator_notes`、depth prompt、extensions；
- 原卡未识别但可安全保存的扩展字段。

原则是“拆字段，不拆角色”。开场白是同一角色模板下的可选择字段/预设，不是多个不同角色。卡内 `character_book` 的每条 entry 则成为独立 MasterItem，并保留其来自哪张角色卡的关系。

### 6.4 LoreEntry

一本设定书对应一个 `source_id`，每条 entry 对应一个 `master_item_id`。除了正文、名称和简介，还要保留 Tavern World Info 常见字段：

```text
keys / secondary_keys / enabled / constant / selective / position / depth
insertion_order / role / probability / group / prevent_recursion / delay / vectorized
```

无法执行的字段仍进入 `source_semantics` 并在兼容报告中说明，不得悄悄删除。

## 7. 翻译与润色流水线

### 7.1 字段级目标

翻译任务从旧的 `name | brief_description | content` 扩展为结构化字段路径，例如：

```text
character.name
character.personality
character.scenario
character.openings[0]
character.mes_example
lore_entry.name
lore_entry.content
```

任务必须携带 `source_id`、`master_item_id`、source revision、字段路径、输入哈希和目标语言。现有 8097 串行队列、缓存、游戏暂停、重试和冲突保护可以复用，但输出目标改为总库 translation version，而不是先写当前冒险 LoreItem。

### 7.2 初译范围

HY-MT 默认翻译所有安全的自然语言字段，而不再只自动翻译名称和简介。模板变量、URL、Markdown、HTML、代码块、正则、脚本和结构键必须保护。

高风险控制字段包括 `system_prompt`、`post_history_instructions`、脚本、正则和会改变角色行为的控制提示。这些字段可以生成译文候选，但不得仅凭普通自动校验就激活，必须人工确认。

### 7.3 状态机与激活

```text
untranslated → hy_mt_active → polish_candidate → polished_active
```

状态机按字段路径维护；一个 MasterItem 可以同时使用不同来源的 active 字段版本，并由 `active_working_revision` 表示这组选择的整体工作版。

- 普通自然语言字段经占位符、数字、结构、标记、非空、长度和 JSON/Markdown 完整性校验后，可自动成为 `hy_mt_active`。
- 高风险控制字段必须人工确认后才能让中文候选 active；确认前继续使用可追溯的原文字段并显示待处理警告，不因自动翻译擅自改变角色行为。
- `polish_candidate` 只代表候选存在，不改变当前工作版。
- 用户接受候选后生成并激活 `polished_active` 版本；原文和旧译本永久保留。
- 任一必需字段失败时，该条目不得被“导入并使用”流程当作全绿完成。

### 7.4 Denova Agent 的职责

Denova Agent 是选择性的字段级校对、纠错和润色器，不负责把所有素材重新全文翻译一遍。它优先处理 HY-MT 校验告警、专名不一致、关键角色字段和用户主动选中的内容。Agent 输出只能成为候选版本，不能覆盖原件，也不能绕过激活步骤直接写入总库或冒险。

## 8. manifest 与追溯

`.narraverse/master-library-manifest.json` 是唯一映射索引，不以目录扫描结果代替。顶层至少包含：

```json
{
  "schema_version": 3,
  "sources": [],
  "items": [],
  "translations": [],
  "instances": [],
  "transactions": [],
  "integrity": {"dangling_references": 0}
}
```

必须支持以下双向追溯：

```text
source_id → source revision → master_item_id → translation_version_id → instance_id
instance_id → master_item_id → active/loaded translation → structured source → immutable original
```

提交 manifest 前执行引用、哈希和 schema 完整性校验。任何悬空引用、损坏文件或哈希不符都必须阻断提交，不能解释为空数据。

## 9. 总库与现有 Narraverse / Denova 的关系

总库是共同上游，不另造一套与项目割裂的数据：

```text
Master CharacterTemplate ─┬─→ Narraverse characterCards[] 投影
                          └─→ Denova LoreItem / opening preset 运行时投影

Master LoreEntry ─────────┬─→ Narraverse backgroundBooks[] 投影
                          └─→ Denova LoreItem 运行时投影
```

现有 `buildTavernCardLoreOperations` 只保留为 `CharacterTemplate → Denova runtime` 的投影兼容层，不再承担总库规范化存储。`.denova/lore/items.json` 同样是运行时投影，不是标准真源。

总库未加载到当前冒险的条目不得进入上下文。云端/本地管家继续复用现有模型 profile 和统一上下文链，但模型只能读取当前冒险已启用的 instance，不能直接改原件或总库 active 版本。

## 10. 两种导入模式

### 10.1 `master_managed`（普通入口，默认）

“导入新素材并使用”保持一次用户操作，后端按单份素材事务执行：

1. 完整读取并计算 SHA-256。
2. 去重或建立 `source_id` 与 source revision。
3. 保存不可变原件。
4. 解析为 CharacterTemplate / LoreEntry，生成 MasterItem。
5. 为安全自然语言字段建立 HY-MT 任务。
6. 保存 translation versions 并校验。
7. 激活允许自动激活的字段；高风险字段等待确认。
8. 生成 Narraverse/Denova 运行时投影。
9. 只有运行所需字段存在有效 active 值后，才为当前冒险创建 `instance_id`。高风险字段可暂时沿用完整原文，但未确认中文候选必须作为可见警告，不能伪装成已完成翻译。

任一步失败只回滚本次未提交事务，不影响其他已成功素材。报告分别显示重复、创建、更新、待人工确认、翻译失败、不支持字段和实例创建结果。

### 10.2 `unmanaged_direct`（高级入口）

直接把素材投影到当前冒险，明确标记：

```json
{
  "management_mode": "unmanaged_direct",
  "master_item_id": null,
  "update_policy": "none"
}
```

它不写总库、不跨冒险复用、不接收总库更新。界面必须提示这是临时路径，并提供以后“提升到总库”的入口；提升时重新走完整原件、身份、翻译和校验流程，不能把当前运行态直接当成可信原件。

## 11. 冒险实例与更新规则

从总库加载时复制当时的 active 中文工作版并生成 `instance_id`。运行记忆、关系、成长、伤势、位置、剧情和本地编辑只写当前冒险。

总库出现新 active 版本时，MVP 只提示“有新版”，由用户明确选择替换；不得静默覆盖实例。替换前保留实例快照和可恢复记录。

Base/Local/Remote 字段级三方合并属于第二阶段：

- `Base`：该冒险上次确认加载的总库版本。
- `Local`：当前冒险实例。
- `Remote`：总库最新 active 版本。

只有 `Local == Base` 的字段可自动接受 Remote；Local 和 Remote 都修改过的同一字段必须产生冲突。MVP 不以整条覆盖冒险，也不提前实现复杂数组合并。

冒险中途加载的新角色默认只加入世界，从下一轮检索开始生效，不自动发送 `first_mes`，也不改写历史对话。用户可显式选择某个 opening 并“加入当前场景”。

## 12. 现有冒险兼容与迁移

MVP 不批量重写既有冒险。旧冒险继续按现状运行；用户以后主动“纳入总库管理”时，优先重新读取其原始素材，在新 ID 契约下导入，并保存 legacy ID 映射。找不到完整原件时必须标为 `best_effort` 或 `incomplete`，不能把旧的截断投影冒充原件。

## 13. 事务、审计与恢复

每份原始素材是独立事务。写入顺序为临时目录 → 原件与结构化解析 → 翻译版本 → MasterItem → manifest → 冒险实例；只有全部引用可解析且哈希正确后才原子提交 manifest。

MVP 至少记录精简事务日志：时间、operation、四级 ID、前后 revision、actor、结果和错误。完整生命周期审计、恢复 UI 和长期日志查询可在第二阶段增强，但原件、版本和失败报告从第一版就不得丢失。

## 14. 对现有实现的复用与修正

### 14.1 可复用

- `material_import.go` 的多文件预览、原件读取、按素材原子边界和冲突报告。
- `character_card.go` 的 PNG/JSON V2/V3 解析、开场白和内嵌世界书识别。
- `MaterialImportDialog.tsx` 的知识库浏览、上传、预览和逐份报告交互。
- 8097 翻译队列的持久化、严格串行、游戏暂停、缓存、重试、占位符保护和冲突检查。
- Denova Lore API 与运行时投影链。

### 14.2 必须修正

- 当前导入目标是“当前 workspace 的 LoreItem”；计划目标改为“总库规范对象，再创建冒险 instance”。
- 当前用户上传来源身份依赖文件名；计划按稳定来源/显式关联/SHA 规则生成 source 谱系。
- 当前角色卡会提前展平成 LoreItem；计划先保存结构化 CharacterTemplate。
- 当前世界书只映射 Denova 已支持字段；计划先完整保存 `source_semantics`，再投影 `runtime_semantics`。
- 当前自动翻译只覆盖名称与简介；计划覆盖全部安全自然语言字段。
- 当前任务结果直接服务 workspace 写回；计划先产生 `translation_version_id` 并由 active 指针决定总库工作版。

因此，现有“资料加载库已实施”不等于本规格的“叙界总资料库已实施”。前者是可靠底座，后者仍需独立实施和迁移验收。

## 15. 分阶段实施范围

### 15.1 MVP

1. 冻结四级 ID、`record_kind`、`semantic_type` 和规范 schema。
2. 建立 sources/items/translations/instances manifest 与完整性校验。
3. 实现不可变原件、CharacterTemplate、LoreEntry 和 World Info 原始语义保存。

## 16. 验收矩阵

- 原件：重复导入不重复保存；同名异内容不覆盖；任意工作版都能回溯原件 SHA。
- ID：`source_id`、`master_item_id`、`translation_version_id`、`instance_id` 职责互不混淆。
- 稳定性：修改 `semantic_type`、中文名、排序或 active 译本不改变条目 ID。
- 角色卡：所有 opening、控制字段、扩展字段和内嵌世界书可追溯，无巨型 Markdown 代替规范模型。
- 世界书：逐 entry 入库，`id=0` 有效，不以数组位置作为永久身份，原始语义不丢失。
- 翻译：全部安全自然语言字段有字段级结果；占位符、数字、Markdown/JSON 结构不损坏；高风险字段不自动激活。
- Agent：只生成可比较候选，不覆盖原件或当前 active 版本。
- 默认导入：普通入口先入总库并通过校验，再创建冒险实例。
- 高级直导：明确不受管、无总库 ID、可在以后主动提升。
- 隔离：两个冒险加载同一条目后，其记忆、关系、成长和本地修改互不可见。
- 更新：总库新版不静默覆盖现有冒险。
- 追溯：任意 instance 可沿 manifest 找到 MasterItem、译本、结构化来源和不可变原件。
- 报告：缺失、冲突、翻译失败、待确认和不支持字段不能显示全绿成功。

## 17. 明确不做

- 不让所有冒险实时引用总库最新版。
- 不把整个总库设为 resident 或每轮全部注入上下文。
- 不覆盖、删除或“清洗后替换”英文原件。
- 不自动把冒险经历或运行状态回写总库。
- 不把 Denova Agent 全量润色设为总库可用的前置条件。
- MVP 不批量迁移或重写所有旧冒险。
- MVP 不实现复杂自动合并、语义搜索或实体图谱。
- 本次规格修订不代表已经修改业务代码、创建总库数据或完成迁移。
