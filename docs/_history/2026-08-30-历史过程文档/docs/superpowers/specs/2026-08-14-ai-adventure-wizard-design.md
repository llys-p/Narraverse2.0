# 在线 AI 冒险创建向导体验改造设计

日期：2026-08-14

## 目标

将现有“设定、职业、角色卡、世界设定卡、冒险文本”混杂的两页创建流程，改造为清晰的三步向导：先选择素材，再由 AI 生成三套差异化故事方案，最后确认并微调后开始冒险。

核心目标：

- 降低创建冒险时的认知负担。
- 让角色卡和世界设定卡真正参与故事背景生成。
- 自动生成完整、可编辑的冒险标题与结构化设定。
- 自定义职业一旦填写便全流程锁定，不再被默认职业覆盖。
- 生成失败或返回异常时保留用户已选内容，可原地重试或跳过 AI 手动创建。

## 三步创建流程

### 第一步：选择素材

顶部显示固定步骤条：`① 选择素材 → ② 故事方案 → ③ 确认开局`。

页面包含：

- 玩家信息：角色名、游戏模式、自定义职业。
- 自定义职业填写后显示“已锁定”状态，清空后解除锁定。
- 素材库：角色卡与世界设定卡两个标签页，保留搜索、分类、预览与勾选能力。
- 已选素材栏：使用紧凑卡片展示已选角色与设定书，并支持移除。
- 故事偏好输入框：选填，可填写节奏、关系、剧情重点及希望避免的内容。
- 主操作按钮：`根据已选素材生成 3 套故事方案`。

不再在第一步显示原有的大段“冒险设定”文本框。没有选择素材时仍允许根据主题、角色名、职业和偏好生成方案。

### 第二步：故事方案

一次生成三套差异明显的故事方案，默认覆盖以下方向：

- 主线冒险型。
- 角色关系型。
- 阴谋或悬疑型。

每套方案包含：

- 冒险标题。
- 一句话卖点。
- 世界背景。
- 玩家身份。
- 职业。
- 起始地点。
- 初始目标。
- 剧情基调标签。
- 已选角色的故事定位与关系摘要。
- 开局钩子。
- 其他说明。

每张方案卡提供“选择此方案”。页面同时提供“重新生成 3 套”和“返回选择素材”。重新生成不会清空素材、职业或偏好。

### 第三步：确认开局

选中方案后自动填入结构化编辑界面：

- 冒险标题，可编辑。
- 世界背景，可编辑。
- 玩家身份，可编辑。
- 起始地点，可编辑。
- 初始目标，可编辑。
- 开局钩子，可编辑。
- 其他要求，可编辑。
- 玩家名称与职业。

自定义职业继续显示锁定状态。已加载角色卡仅显示头像、名称、故事定位与关系摘要；已加载世界设定卡仅显示标题、分类与简介，详细原文通过预览查看，不在确认页展开全部字段。

底部提供“返回故事方案”和“开始冒险”。开始后直接使用开局钩子生成第一幕。

## 临时数据模型

三套未选方案仅存在于当前创建会话，不写入正式冒险存档：

```js
{
  id,
  title,
  pitch,
  world,
  playerIdentity,
  profession,
  location,
  goal,
  toneTags: [],
  cast: [{ name, role, relationship }],
  openingHook,
  other
}
```

创建会话新增临时状态：

- `adventureStoryPreference`：用户选填偏好。
- `generatedStoryProposals`：最多三套方案。
- `selectedStoryProposalId`：当前选中方案。

## AI 生成契约

输入由以下内容组成：

- 当前主题与游戏模式。
- 玩家名称。
- 自定义职业或当前选定职业。
- 用户故事偏好。
- 已选角色卡的名称、外貌、性格、关系、背景与开场信息摘要。
- 已选世界设定卡的标题、简介及限长正文。

AI 返回包含三套对象的 JSON。前端需要：

- 清理 Markdown 代码围栏。
- 从回复中提取第一个合法 JSON 数组或对象。
- 对字段进行归一化和默认值补齐。
- 丢弃无法解析的单套方案；至少一套合法即可展示。
- 不足三套时显示已成功生成的方案并提供重新生成入口。

提示词明确要求三套方案在主要冲突、玩家身份、开局事件和叙事重心上有明显差异。

## 职业锁定规则

自定义职业是最高优先级且唯一可信来源：

1. 自定义职业非空时，清空普通职业选中状态。
2. AI 生成请求将自定义职业作为不可修改约束。
3. AI 返回后，前端强制把每套方案的职业覆盖为自定义职业。
4. 选择方案、返回上一步、重新生成和开始冒险均不得修改该值。
5. 自定义职业为空时，才允许使用方案推荐职业或主题默认职业。

## 正式冒险字段映射

选中方案后映射到现有冒险结构：

- `title` ← 方案标题。
- `settingParts.world` ← 世界背景。
- `settingParts.identity` ← 玩家身份。
- `settingParts.goal` ← 初始目标。
- `settingParts.other` ← 其他说明。
- `state.adventureLocationOverride` ← 起始地点。
- `customProfession` 或 `state.selectedProfession` ← 锁定职业或方案职业。
- `openingSeed` ← 开局钩子。
- `characterCards/backgroundBooks` ← 第一步选中的素材。

正式存档不保存未选中的方案。

## 失败处理

- 未配置 API 时打开设置页，创建会话数据不清空。
- 生成中禁用重复提交并显示阶段提示。
- 网络失败、超时或 JSON 解析失败时保留所有输入，显示错误并允许重试。
- 至少一套合法方案即可进入第二步。
- 用户可以跳过生成，在第三步手动填写结构化字段。
- 返回前一步时保留偏好、素材、职业、已生成方案和当前选择。

## UI 与样式

- 创建弹窗保持桌面宽屏布局，但每一步只展示当前任务相关内容。
- 第一步采用玩家信息区、素材区和已选素材栏，不再堆叠全部表单。
- 第二步采用三列大型方案卡；窄窗口降为单列。
- 第三步采用结构化分区卡片，角色卡和设定书只展示摘要。
- 生成状态、职业锁定和已选方案使用清晰的状态徽标。
- 复用现有视觉变量与按钮体系，在 `redesign.css` 增加向导专用样式。

## 涉及文件

- `app/index.html`：三步向导结构、偏好输入、方案容器和确认页锚点。
- `app/app.js`：临时状态、AI 生成与解析、职业锁定、方案选择、字段映射、开始冒险流程。
- `app/redesign.css`：步骤布局、已选素材栏、方案卡和确认页样式。
- `.workbuddy/tmp/test_adventure_wizard.js`：扩展现有创建向导回归。
- `代码指南.md`：同步新建冒险数据流、函数与临时状态。
- `项目协作日志.md`：按时间倒序记录修改内容与验证结果。

## 验收标准

- 可根据已选角色卡、世界设定卡和偏好生成最多三套差异化方案。
- 每套方案均自动生成冒险标题。
- 选择方案后完整填入第三步的结构化字段。
- 自定义职业在生成、选方案、返回、开始冒险后均保持不变。
- 生成失败不会丢失素材、偏好或职业。
- 未使用 AI 时仍可手动创建冒险。
- 开始冒险后左侧列表显示生成或编辑后的冒险标题。
- 第一幕使用选中方案的开局钩子。
- JS 语法检查和扩展后的创建向导无头回归通过。
