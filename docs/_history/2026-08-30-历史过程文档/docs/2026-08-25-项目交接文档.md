## 2. 项目到底是什么

### 2.1 产品定位

- **【已确认】**产品名为“叙界 Narraverse”。
- **【已确认】**核心体验是 AI 辅助的文字冒险 / 角色扮演：玩家提供角色、世界、偏好和行动，系统返回叙事、状态变化和后续选择。
- **【已确认】**Denova 同时承担写作工作台和结构化互动游戏能力，因此叙界不是 Denova 的独立启动程序，而是 Denova 的第三种顶层模式。
- **【推测】**当前产品更像“AI 叙事创作与互动游戏平台”，而不是已经收敛为单一玩法的成品游戏。

### 2.2 当前核心游戏循环

在线叙界真实循环：

```text
玩家创建 / 载入冒险
→ 载入角色卡、世界设定卡、偏好和故事方案
→ 生成或编辑冒险标题、背景、身份、地点、目标
→ 玩家输入行动或选择选项
→ app.js 组织当前状态、历史、设定书和提示词
→ 调用玩家配置的 LLM
→ 解析 [NARRATIVE] / [STATE] / [CHANGES] / [CHOICES] 等区块
→ 写回角色、任务、剧情节点、摘要、时间轴等前端状态
→ 渲染叙事、选项、属性面板和事件记录
→ 保存到 IndexedDB，并按条件向 Denova 桥接同步
→ 进入下一轮行动
```

离线小说线真实循环：

```text
选择离线设定包
→ GameEngine 初始化局内状态
→ 玩家选择行动
→ 本地事件图 / d20 检定 / 战斗规则处理
→ 更新 HP、资源、事件、章节和结局状态
→ 渲染事件文本、选项和火柴人动作
→ 继续下一事件或进入结局
```

Denova 互动线真实循环：

```text
选择 Denova 工程 / 互动模式
→ 加载 lore、章节和结构化快照
→ Agent 根据历史与工具协议准备回合
→ 服务端校验并提交 TurnEvent / StateDelta
→ 追加 JSONL 事件和快照
→ 前端显示叙事、选项和状态
→ 玩家继续下一回合
```

**不要把三条循环当成同一套规则。**它们现在只在入口、部分素材和部分同步字段上相连；游戏状态、规则裁定和存档真源仍然不同。

### 源码、快照、运行数据三层原则

1. 改叙界功能：先改 `app\`。
2. 改完后同步到 `denova-src\web\public\narraverse\`，再按部署流程更新 `denova\web\narraverse\`。
3. 不要只编辑 `denova\web\narraverse\`，否则下次部署会被覆盖。
4. 不要把 `denova\.denova\` 的现有用户数据当成源码提交或随意清空。
5. 本次核对显示 `app\` 与当前部署的 `index.html`、`style.css`、`app.js` 哈希一致；未来每次代码修改后仍需重新核对。

## 5. 数据真源与流转

### 5.1 在线冒险数据

核心对象是 `state` 与 `adventures[]`，具体字段以 `app\app.js` 的初始化、`stateToJson()`、`saveState()`、`createAdventure()` 为准。

大致包含：

- 玩家：姓名、身份 / 职业、属性、HP / MP、等级、EXP、技能、装备 / 背包、位置、情绪。
- 冒险：标题、世界背景、起始目标、章节、开场钩子、对话历史、任务、剧情节点、事件时间轴、上下文摘要。
- 素材：角色卡、世界设定卡、设定书、导演台和场景预设。
- 同步：`syncMeta`、Denova 工程标识、同步状态和最后写入信息。

### 5.2 Denova 数据

- 工程注册：`denova\.denova\books.json`。
- 工程内容：`denova\.denova\projects\<工程>\`。
- lore：工程目录中的 lore 文件 / 条目。
- 互动故事：`interactive\story\index.json`、事件文件和快照相关目录。
- 会话：部分工程存在 `.denova\sessions\` 下的 Agent 会话记录。
- **【建议】**不要直接删除 `.denova\projects`；如果需要实验，先复制工程到临时目录并在 `books.json` 注册独立测试工程。

### 5.3 AI 参与边界

在线线：

- **【已确认】AI 负责**：叙事、选项、世界回应、状态变更建议、任务 / 剧情文本、摘要和部分标题 / 背景生成。
- **【已确认】前端负责**：调用、协议解析、状态写回、渲染和持久化。
- **【风险】**在线战斗和部分状态结论仍依赖 AI 遵守文本协议，尚未完全变成不可绕过的确定性规则层。

离线线：

- **【已确认】本地引擎负责**：检定、数值、战斗、事件转移、结局。
- **【已确认】AI 只负责**：可选的表现层文本和动作标签。

Denova 互动线：

- **【已确认】Agent 负责**：根据 lore、历史和工具协议提出互动回合。
- **【已确认】Denova 服务端负责**：工具准备、提交、父状态 / schema / 规则校验和事件追加。
- **【待确认】**当前所有 Agent 调用是否都经过同一套服务端校验；接手代码时应从 `story.go`、`story_snapshot.go` 和互动 Agent 工具定义核对。

## 8. 启动与排障手册

### 一键启动

```text
<project-root>\Launch-Narraverse.cmd
```

它会尝试：

1. 启动 `tools\denova_bridge.py`，健康检查 `http://127.0.0.1:8097/api/denova/health`；
2. `pixiv_config.json` 存在且配置可用时启动 8098 Pixiv 桥；
3. 启动 `denova\denova.exe`；
4. 探测 Denova 前端，打开 `/?mode=narraverse`。

启动脚本：`<project-root>\tools\start_narraverse.ps1`。

### 不弹窗口是否正常

- **【已确认】**桥和 Denova 都使用隐藏窗口启动，正常情况下不会出现黑色控制台。
- 查看桥日志：`<project-root>\tools\logs\`、`<project-root>\tools\denova_bridge*.log`。
- 查看 Denova 日志：`<project-root>\denova\log\`。
- 当前发布版优先探测 8080 到 8090，也兼容开发端口 5173 到 5190。

### 手机访问

```text
http://<电脑局域网IP>:8080/narraverse/index.html?mobile=1
```

- 直接访问叙界时保留 `mobile=1` 可以强制移动布局。
- 从 Denova `/?mode=narraverse` 进入时，iframe 会根据自身宽度自动切换移动布局。
- 如果手机访问失败，先确认 Denova 是否监听 `0.0.0.0:8080`，不要直接恢复旧的 8081 结论。

### 动态模块加载失败

出现 `Failed to fetch dynamically imported module` 时，优先按以下顺序排查：

1. Denova 进程是否启动后立即退出；
2. 8080 是否被旧进程占用；
3. `denova\log\` 是否只写了开头几行；
4. 是否浏览器缓存了不匹配的旧部署快照；
5. `denova\web\assets\` 与当前 `denova.exe` 是否来自同一次部署。

不要第一时间修改 React 路由或叙界业务代码。
