# 叙界 Narraverse · 项目梳理与优化方案

> 生成时间：2026-08-22 ｜ 视角：叙界本体 = 两条玩法线（两平台）+ 统一宿主 Denova
> 依据：`CODE_GUIDE.md`、`COLLABORATION_LOG.md`、`AI_COLLABORATION_GUIDE.md`（均位于 `<project-root>`）

---

## 0. 先回答你问的"两平台"是什么

叙界 Narraverse 本质是一个**纯静态单页（SPA）**，无构建、无后端，全部逻辑集中在 `app/app.js`。它内部跑的是**两条玩法线（即你说的两平台）**，外面包一层 **Denova 统一宿主**：

| 名称 | 定位 | 是否"平台" |
|---|---|---|
| **在线冒险线** | LLM API 驱动的在线文字冒险 | ✅ 平台一 |
| **离线小说线** | 引擎驱动、可完全离线的结构化小说游戏 | ✅ 平台二 |
| Denova 宿主 | 统一外壳（iframe 嵌入 + 桥接同步） | 外壳，不是玩法线 |

> 若你口中的"两平台"是"叙界 + Denova"这对产品组合，本文档同样覆盖——Denova 作为宿主在 §1.3 单列。

两线**共用同一套 `state` 与 `renderAll` 渲染**，但底层引擎完全不同：在线线靠 LLM 协议解析，离线线靠本地事件图。这正是"混乱感"的主要来源（见 §2）。

## 1. 两平台逐一拆解

### 1.1 平台一 · 在线冒险线（LLM 驱动）

- **核心文件**：`app.js`（`callLLM` SSE 流式、`buildSystemPrompt` 提示词管线、`[NARRATIVE][STATE]…[PLOT]` 协议解析）、`local_library.js`（自动生成的知识库 / World Info 源数据，**禁止手改**）
- **玩法**：联网，AI 即兴叙事；支持上下文压缩、前情摘要查看/编辑、角色状态追踪、横向时间轴事件记录、AI 冒险简介
- **已长出的子系统**（都挂在在线线或横切层）：
  - 三步创建向导（选择素材 → AI 生成 3 套故事方案 → 确认开局）
  - 导演台（右栏 🎬 Tab，协议扩展 `[EVENTS]/[CHECK]`，题材映射 Denova 18 预设）
  - 写作工程化（大纲/细纲 `adventure.novelPlan` + 版本账本 `adventure.versionLedger`）
  - 场景预设（5 内置：灵感探索/严肃长篇/互动游戏/快速试玩/世界观构建，随 Work 保存）
  - 生图（Qwen-Image-3.0-Pro，DashScope）、TTS（native / CosyVoice）、Pixiv 搜图（本地桥接 :8098）

### 1.2 平台二 · 离线小说线（引擎驱动，可选 AI 增强）

- **核心文件**：`app/game_engine.js`（事件图 + 检定 d20 + 战斗 + 结局）、`app/packs/limitless.js`（内容包）、`app/stickman.js`（右侧火柴人可视化）
- **入口**：`GameEngine.open()`
- **玩法**：**默认完全离线、不依赖任何 API**；数值/检定/战斗/结局逻辑始终走本地
- **可选 AI 增强**：界面「✨ AI 增强」开关（**默认关**）开启且 `state.apiConfig` 已配时，复用全局 `callLLM` 扩写事件叙事/选项结果/战斗结局/副本序章，并解析回复末尾 `<action:xxx>` 驱动火柴人（`idle/walk/run/attack/cast/hit/…`）；AI 失败自动回退；事件级 AI 文本按 `pack.id+事件id` 缓存到 `localStorage`，`headless` 路径不触发 AI
- **适用**：无网环境、确定性玩法、可复现的章节进度

### 1.3 统一宿主 · Denova

- **嵌入方式**：`?embedded=denova` 同源嵌入为 Denova 第三顶层模式；`app.js` 启动即解析写入 `body.dataset.host`（只控外壳通信，不改 Adventure 数据模型）
- **桥接协议**：`app/bridge.js` v1 `postMessage`（origin 白名单 + `event.source===window.parent`）；叙界发 `ready`/`switch-mode`，Denova 发 `theme-changed`/`locale-changed`
- **数据同步**：`tools/denova_bridge.py`（:8097）双向同步（lore / 四段设定 / 摘要 / 角色素材 / 章节）；仅新冒险写 `syncMeta`，旧冒险不迁移
- **唯一入口**：`Launch-Narraverse.cmd` → 自动启动 8097 同步桥（+可选 8098 Pixiv 桥）+ Denova → 打开 `/?mode=narraverse`

## 2. 你感到的"混乱"从哪来（诊断）

1. **`app.js` 单体约 5000 行**：两线 + 全部横切子系统（导演台/版本账本/时间轴/场景预设/UI 重设计/知识库/Pixiv/生图/TTS/手机适配）共住一个文件，定位成本高。
2. **两线"共用 state 与 render"但引擎迥异**：在线靠 LLM 协议、离线靠事件图，边界只在脑子里，改一处怕动另一条——这是"混乱感"的核心。
3. **Denova 第三层叠加**：iframe + bridge + 同步桥 + 跨来源 IndexedDB 迁移提示 + 发布端口回退，心智负担成倍。
4. **功能爆炸**：2026-08-11→08-22 约 130 条协作记录，导演台/版本账本/时间轴/场景预设/UI 重设计/知识库/Pixiv/生图/TTS/手机适配 在两周内迅速累积，缺乏"森林视图"。
5. **文档过载**：`CODE_GUIDE.md` 63KB + `COLLABORATION_LOG.md` 141KB + `docs/` 多份规划书（v1/v2/v3/v4、结合方案、现状分析报告…），找不到重点。
6. **路径残留**：已统一到 `<project-root>`（`app/`、`denova/`、`denova-src/`、`knowledge-base/`），但旧 `<external-text-adventure-project>`、`<external-denova-installation>*` 仍被部分日志/脚本引用（如迁移前的功能记录仍写 `<external-text-adventure-project>\app\...`）；旧 `<external-text-adventure-project>` 现仅作小说抓取参考，却仍是一个独立工作区，易误当主项目。
7. **多 AI / 多外部代理口径不一**：AI1/2/3 + Codex + MainAgent + UI Designer 各自落日志，部分记录引用旧路径、新旧项目根混用。

## 3. 优化方案（五步收敛）

### A. 代码分层矩阵（P0，不改行为，先理地图）
- 在 `CODE_GUIDE.md` §0 补一张 **「功能 → 文件 → 属于哪条线」矩阵**，并加 **「10 秒定位表」（我要做 X → 看 §Y）**。
-  mentally（或后续物理）把 `app.js` 按职责分区：
  - `online/`：在线线专属逻辑（协议解析、提示词管线、导演台、写作工程化）
  - `offline/`：离线线桥接（GameEngine 调用、火柴人动作映射）
  - `shell/`：Denova / bridge / 启动器
  - `core/`：state / renderAll / callLLM / saveLoad（两线共享，下沉到此）
  - `features/`：时间轴、版本账本、Pixiv、生图、TTS 等横切

### B. 两线边界显式化（P0，消除"改一处怕动另一条"）
- 在线线只读 `adventures[].type==='adventure'`，离线线只读 `type==='tavern'/offline`；渲染与状态分派加 **type guard**。
- 共用能力（`callLLM` / `renderAll` / `saveState`）严格下沉 `core/`，禁止两线互相 `import` 对方具体函数。
- 在 `CODE_GUIDE` 标注每个导出函数的「归属线」，新 AI 接手一眼看清边界。

### C. 文档导航化（P1，立刻降认知负荷）
- `CODE_GUIDE` 顶部加锚点目录 + 10 秒定位表；把"铁律/当前状态/各 AI 登记/功能记录"用 `##` 锚点串起来。
- `COLLABORATION_LOG.md`（141KB）拆出 **`CHANGELOG-2026-08.md` 精简版**（仅功能记录表 + 进行中任务），完整版留作审计。
- `docs/` 多份规划书统一归档进 `docs/归档/`，只保留 1 份现行（现状分析报告 + 整合规划 v4）。

### D. 路径与残留清理（P1）
- 旧 `<external-text-adventure-project>`：确认仅作抓取参考后，把抓取脚本 + 小说移入 Narraverse 的 `reference/`（或独立仓库），**删除空壳**，避免误当主项目。
- 扫描并替换 `COLLABORATION_LOG` / 脚本中残留的 `<external-denova-installation>*`、`<external-text-adventure-project>\app` 旧引用。

### E. 统一协作口径（P2，长期不腐）
- 锁定"唯一真实根 `<project-root>`"，所有新日志/脚本禁止写旧路径。
- 外部代理（Codex / MainAgent / UI Designer）输出统一回写 Narraverse 路径，避免再次分裂。
