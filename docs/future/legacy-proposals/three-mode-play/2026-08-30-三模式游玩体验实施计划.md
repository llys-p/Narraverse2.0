# 三模式游玩体验实施计划

- 日期：2026-08-30
- 依据规格：[三模式游玩体验设计](../specs/2026-08-30-三模式游玩体验设计.md)
- 状态：待用户确认，尚未修改生产代码

## 1. 实施原则

1. 先减轻前台体验，再调整后台调度，避免同时改动多个不易回滚的链路。
2. `<project-root>\app` 仍是独立叙界的唯一源码；修改后通过既有同步脚本部署到 Denova 内嵌资源。
3. 旧故事、旧存档和没有标签的旧数据继续可读，缺失标签按空数组处理。
4. 前台停用导演台不等于删除任何导演代码；组件、接口、数据文件和测试全部先保留。
5. 每完成一个阶段都运行定向测试，再进入下一阶段。

## 2. 阶段一：冒险标签数据契约

### Denova 原生规则冒险

修改范围：

- `denova-src/internal/interactive/story_types.go`
- `denova-src/internal/interactive/story.go`
- `denova-src/web/src/features/interactive/types.ts`
- `denova-src/web/src/features/interactive/opening.ts`
- `denova-src/web/src/features/interactive/components/NewStorySetupPanel.tsx`
- `denova-src/web/src/features/interactive/components/InteractiveLayout.tsx`
- 对应中英文 i18n 文案和测试

实现要点：

- 增加故事级 `story_tags` 字段，包含标准化后的标签数组和可选主要标签。
- 创建、编辑、读取、索引和 JSONL meta 全链路保存标签。
- 标签数量限制为 3～5 个；去重、去空格、限制长度；旧数据缺失时返回空数组。
- 创建/编辑故事时提供气质、节奏、重点三组紧凑选择，不暴露导演术语。
- 将标签以低优先级上下文注入互动故事提示词，明确“只影响倾向，不覆盖玩家行动和世界事实”。

### 独立叙界

修改范围：

- `app/app.js`
- `app/index.html`
- `app/redesign.css`
- 现有无头回归测试台或新增最小标签测试

实现要点：

- 在冒险对象中增加兼容字段，例如 `storyTags`，默认空数组。
- 创建/编辑冒险时复用标签芯片选择，最多保留 5 个。
- 在 `buildTavernSystemPrompt` 和规则冒险提示词中注入标签约束。
- 冒险列表只显示最多 2～3 个标签作为辅助信息，不在正文区反复显示。
- 标签随 IndexedDB/localStorage 状态保存，并通过现有 Denova 同步数据链路传递。

验收：新建带标签和不带标签的故事，刷新、切换入口、旧存档读取均不丢数据。

## 3. 阶段二：停用游玩前台导演台

修改范围：

- `denova-src/web/src/features/interactive/components/InteractiveLayout.tsx`
- `denova-src/web/src/features/interactive/components/StoryStage.tsx`
- 导演台相关 i18n、导航和测试

实现要点：

- 停止在故事页面挂载右侧 `DirectorPanel`。
- 停用故事页“显示/隐藏导演台”按钮和移动端导演台入口。
- 不让 `director` 成为玩家游玩时的一级子模式。
- `DirectorPanel`、`DirectorBackstage`、`DirectorConsole`、相关 i18n、测试及后台 API 均不删除，仅从玩家前台断开，保留后续恢复或迁移空间。
- 保留故事导演选择作为高级故事配置，但文案改为不要求玩家理解后台流程。
- `StoryStateLedger` 不再作为每回合完整状态面板，只保留阶段三定义的上下文摘要。

验收：故事页面不显示导演台、右侧状态栏或导演运行文档；对应组件、接口和数据仍存在；已有故事仍可正常发送和读取快照。

## 4. 阶段三：沉浸对话的稳定输出

修改范围：

- `denova-src/web/src/features/interactive/components/StoryStage.tsx`
- `denova-src/web/src/features/interactive/components/story-stage/live-stream-messages.ts`
- `denova-src/web/src/components/Chat/AgentMessageList.tsx`
- `denova-src/web/src/components/Chat/MessageItem.tsx`
- 相关流式和滚动测试

实现要点：

- 保留 SSE 和停止生成能力，但将正文 chunk 先放入缓冲区。
- 沉浸对话默认在正文完成后一次性提交；不对每个 token 触发 Markdown 树重建。
- 生成期间只显示稳定的活动状态，占位区域尺寸不随文本增长而变化。
- 思考、工具调用和后台状态事件不进入沉浸对话正文流。
- 用户在底部时可以在完成后跟随到新回复；用户离开底部后保持阅读位置。
- 规则冒险可保留必要的过程状态，但也必须按阶段或完整事件批量更新。

验收：连续生成长回复时阅读区不逐字跳动；向上阅读历史后不会被新 chunk 抢回底部；停止、错误、重试和恢复仍可用。

## 5. 阶段四：规则信息按情境披露

修改范围：

- `denova-src/web/src/features/interactive/components/StoryStage.tsx`
- `denova-src/web/src/features/interactive/components/story-state/ChangesSummary.tsx`
- 新增或重构规则反馈组件及其测试

实现要点：

- 普通回合只显示一行变化摘要，最多展示少量变化项。
- 战斗显示战斗双方和可行动作；检定显示检定结果和简短原因；升级显示成长结果。
- 详细属性、背包、任务和角色状态放入按需打开的“角色状态”界面。
- 不再使用完整右侧导演台承载玩家状态。
- 没有变化时不渲染空的状态区域。

验收：无战斗、无检定、无升级的回合不出现大块属性区域；发生规则事件时信息完整且可回看。

## 6. 阶段五：后台导演解耦

修改范围：

- `denova-src/web/src/features/interactive/components/StoryStage.tsx`
- `denova-src/web/src/features/interactive/components/InteractiveLayout.tsx`
- `denova-src/internal/interactive` 中导演调度和回合完成链路
- 对应导演运行测试

实现要点：

- 正文持久化成功后立即结束玩家可见回合，不等待后台导演规划完成。
- 导演运行默认采用关键事件/按需/每 3～5 回合策略，具体沿用已有策略字段。
- 导演失败只记录状态，不阻塞正文、选项或下一次输入。
- 保留幂等、分支和 CAS 保护，避免后台异步写入覆盖玩家新回合。
- 将冒险标签作为导演和正文 Agent 都可读取的偏好，但不提升到覆盖事实的优先级。

验收：后台导演延迟或失败时，玩家仍能看到完整正文、继续阅读，并获得明确的非阻塞提示。

## 7. 验证与发布顺序

1. 运行 Denova 互动模块定向测试：类型、创建编辑、故事阶段、滚动、状态摘要和导演调度。
2. 运行独立叙界无头回归：旧存档加载、标签持久化、提示词注入、流式输出、选项和状态应用。
3. 执行 `pnpm build`。
4. 用既有 `pnpm sync:narraverse <project-root>\app` 同步独立叙界资源。
5. 部署到 `denova/web` 前先完成暂存与备份，再替换构建产物。
6. 真实运行态检查沉浸对话、规则冒险、创建/编辑标签、战斗/检定/升级、错误和停止。
7. 检查 390px、桌面宽屏、深色主题、键盘焦点和 reduced motion。
8. 更新项目协作日志，记录测试结果和任何新踩坑。

## 8. 风险与回滚

- 若流式缓冲影响用户对“正在生成”的感知，保留轻量活动状态，不恢复 token 级正文重排。
- 若规则事件字段不足以生成上下文卡，先复用现有 `RuleResolution`、`TurnResult` 和 `StateDelta`，不改动底层协议。
- 若后台导演异步写入与新回合发生竞争，优先丢弃过期导演结果，不覆盖最新分支状态。
- UI 停用阶段只断开渲染和入口，不删除任何导演组件、接口和数据文件，必要时可恢复旧入口。
- 标签字段新增必须保持可选，旧版本数据不因缺失字段而失败。

## 9. 实施完成定义

只有以下条件全部满足，才视为完成：

- 三模式入口和职责清晰。
- 游玩页没有启用的导演台和常驻全量状态；导演相关代码与数据仍可恢复。
- 沉浸对话正文不再逐 token 跳动。
- 规则冒险仍能完成战斗、检定、升级和回溯。
- 冒险标签可以创建、编辑、持久化并影响剧情倾向。
- 后台导演延迟或失败不阻塞玩家。
- 旧存档、Denova 内嵌入口和独立 HTTP 入口均通过验证。
