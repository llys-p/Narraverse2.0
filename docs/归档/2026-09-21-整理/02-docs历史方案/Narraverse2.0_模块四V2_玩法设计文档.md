# Narraverse2.0 模块四 V2 玩法设计文档

> 文档定位：玩法与体验基线
> 当前方向：事件驱动的多智能体自由沙盒世界
> 状态：概念方案已确定，进入后续规格拆解前的玩法基线

---

## 1. 模块四 V2 的核心定义

模块四不再以“任务、检定、固定剧情流程”为核心，而是改造成一个：

**事件驱动的多智能体自由沙盒世界。**

这个世界有自己的时间、地点、人物、关系、事实和事件。玩家不是世界唯一的中心，也不是每件事都必须围绕玩家发生。

玩家可以自由行动，NPC 也拥有自己的目标、记忆、情绪、关系和计划。只有当事件真正发生、时间节点到达、玩家接触某个角色，或者某个角色的计划需要继续推进时，对应的 AI 才会被唤醒。

因此，玩家感受到的是一个“持续存在、会自己变化”的世界，但后台并不会让所有 AI 一直运行。

核心体验可以概括为：

> **世界先存在，人物在其中生活；玩家进入其中行动，事件发生时才让相关角色真正“活过来”。**

---

## 2. 设计目标

模块四 V2 追求的不是传统文字冒险的“选项推进剧情”，而是以下体验：

- 玩家可以直接输入任何合理行动，而不是只点预设按钮。
- NPC 不是由同一个“全知 AI”统一扮演，而是拥有各自独立的认知和行为。
- NPC 可以在玩家看不到的地方互动、产生计划和改变关系。
- 玩家默认只能知道自己能够看到、听到、推断到的信息。
- 世界的变化会沉淀成事实、记忆和历史，而不是每轮对话结束后重新编一次。
- 长期游玩时，上下文不会无限膨胀，而是按事件主动检索真正相关的知识。
- 后续可以与 Obsidian 结合，让世界运行过程中不断长出人物、地点、事件、事实和每日记录节点。

---

## 3. 世界生成阶段

正式游玩前，先进行一次“造世界”。

玩家可以向系统提供：

- 世界背景
- 世界规则
- 时代与社会环境
- 角色卡
- 势力或组织
- 已知地点
- 已知人物关系
- 重要历史
- 玩家自己的身份设定

系统根据这些资料生成一个可以运行的世界骨架。

### 3.1 世界骨架

世界初始生成后，应至少包含：

**世界**
- 世界名称
- 基础背景
- 当前日期与时代
- 世界规则
- 公共事实
- 核心矛盾或长期变化因素

**地点**
- 城市
- 区域
- 建筑
- 房间或小型场景
- 地点之间的连接关系
- 地点的用途和开放条件

地图本质上不是一张死图片，而是一个可以变化的地点关系网络。

例如：

```text
城市
├─ 商业区
│  ├─ 公司
│  │  ├─ 办公区
│  │  └─ 会议室
│  └─ 酒吧
├─ 住宅区
│  ├─ 玩家住所
│  └─ 林雨住所
└─ 大学区
   ├─ 教学楼
   └─ 图书馆
```

后续可以再把这个地点网络可视化为地图。

### 3.2 人物落位

导入角色后，不只是把角色卡放进资料库，而是让人物真正进入世界。

每个 NPC 会获得：

- 住所
- 工作或主要活动区域
- 常去地点
- 初始关系
- 当前状态
- 当前目标
- 已知事实
- 不知道的事情
- 私人秘密
- 初始计划或事件种子

因此角色卡解决“这个人是谁”，世界生成阶段解决“这个人现在生活在哪里、正在做什么”。

### 3.3 场景按需生成

世界生成时不需要把每一个地点的所有细节都写完。

地点只保存稳定骨架。

玩家真正进入某个地方时，再根据：

```text
地点骨架
+ 当前时间
+ 天气
+ 在场人物
+ 最近发生的事件
+ 地点历史
```

生成当前的具体场景。

这样世界既有连续性，又不会在开局时花大量 token 生成玩家可能永远不会去的地方。

---

## 4. 玩家实际看到的界面

日常游玩默认采用**玩家视角**。

玩家看不到：

- NPC 的隐藏想法
- NPC 的完整计划
- 尚未发现的秘密
- 玩家不在场时发生的全部内部过程
- AI 调度过程
- 原始 JSON
- 世界后台状态机
- 模型调用日志

玩家真正看到的只有：

- 当前日期与时间
- 当前地点
- 当前可感知场景
- 在场人物
- 当前发生的事情
- 对话与行动结果
- 一个自由输入框

例如：

```text
9 月 3 日 · 18:20
公司 · 休息区

林雨坐在靠窗的位置，杯子里的咖啡几乎没动。
她看起来比平时安静。

你想做什么？

> 我走过去坐到她旁边，问她今天是不是出了什么事。
```

模块四 V2 的主界面应该始终让“当前世界”位于视觉中心，而不是把系统诊断信息摆在玩家脸上。人类玩游戏，通常并不是为了欣赏 JSON。

---

## 5. 玩家自由行动

玩家不需要从固定按钮里选择行为。

可以直接输入：

- 去某个地方
- 找某个人
- 和某人聊天
- 打电话
- 偷听
- 工作
- 睡觉
- 等待
- 旅行
- 表白
- 撒谎
- 调查
- 打架
- 什么也不做
- 任何符合当前世界条件的自由行为

系统首先判断这次行为涉及什么。

例如：

```text
玩家输入
“我去酒吧找林雨。”

↓

系统判断
移动 + 寻人

↓

检查
酒吧是否存在
当前位置是否可达
当前时间是否允许
林雨是否可能在那里
```

确定性问题优先由世界规则判断，而不是把所有问题都问 AI。

---

## 6. NPC 不是一个 AI，而是多个独立角色 Agent

这是新版模块四最核心的变化之一。

每个重要 NPC 都拥有自己的独立“角色脑”。

一个 NPC Agent 只知道自己应该知道的东西。

例如林雨可能知道：

- 自己下午和陈雪吵架
- 自己今晚想联系陈雪
- 玩家刚刚问过她什么

但她可能不知道：

- 老板已经偷偷拿走文件
- 陈雪昨晚和另一个角色见过面
- 玩家曾经在另一个地点调查她

除非这些信息后来通过合理方式进入她的认知。

因此必须区分：

### 世界事实

真正已经发生的事情。

### NPC 认知

这个 NPC 相信或知道什么。

NPC 的认知可以：

- 正确
- 错误
- 不完整
- 被欺骗
- 被遗忘

### 玩家已知信息

玩家本人当前知道什么。

这三者不能混成一份资料，否则秘密、误会、谎言和调查玩法都会失去意义。

---

## 7. NPC Agent 按需唤醒

NPC 不会 24 小时持续运行 AI。

它们平时只保存：

- 当前状态
- 当前目标
- 当前意图
- 下一个可能触发的时间
- 未完成事件

只有以下情况才真正唤醒：

1. 玩家直接接触该 NPC。
2. 另一个 NPC 的行为影响了他。
3. 某个计划到达执行时间。
4. 世界事件影响了他。
5. 某个重要事实发生变化。
6. 系统需要他做出真正影响世界的决定。

例如：

```text
18:20
玩家询问林雨。

→ 唤醒林雨 Agent
→ 林雨决定回避问题
→ 同时形成一个私人意图：
   “今晚联系陈雪。”

19:30
意图到期。

→ 再次唤醒林雨
→ 林雨发送消息给陈雪

消息影响陈雪。

→ 唤醒陈雪 Agent
→ 陈雪决定是否回复
```

玩家可能完全不知道 19:30 发生的后台互动。

直到：

```text
20:10
玩家收到林雨消息：

“明天有空吗？有件事想跟你说。”
```

世界因此显得在玩家视野之外也继续存在。

---

## 8. 世界裁判

NPC Agent 不能直接随意修改世界真相。

NPC 只负责表达：

- 自己想做什么
- 自己说什么
- 自己如何反应
- 自己的情绪和判断变化

真正决定“事情是否发生”的，是世界裁判层。

例如：

两个 NPC 同时想拿走同一个物品。

不能让两个 Agent 都写：

> 我成功拿走了文件。

而应该是：

```text
NPC A：尝试拿文件
NPC B：试图阻止

↓

世界裁判
结合位置、时间、能力、已有事实和冲突规则

↓

最终结果
A 没能拿走文件
双方发生争执
文件仍在原处
```

然后才把结果写入世界事实。

因此新版的核心原则是：

> **NPC 决定意图，世界决定结果。**

---

## 9. 一次完整行动如何发生

一次普通玩家行动可以按照以下顺序运行：

```text
玩家自由输入
↓
理解玩家意图
↓
读取当前世界状态
↓
判断涉及的地点 / 人物 / 物品 / 事件
↓
检索真正相关的知识和记忆
↓
唤醒必要的 NPC Agent
↓
NPC 分别给出自己的反应与意图
↓
世界裁判解决结果
↓
生成正式事实
↓
更新人物状态、关系、记忆和事件
↓
生成玩家能看到的现场叙述
↓
返回玩家
```

普通行动应尽量只触发少量 AI 调用。

只有多人冲突、大型事件或复杂社交场景，才需要唤醒多个角色。

---

## 10. 世界不会持续疯狂预演

新版不采用“后台所有人物一直调用 AI 进行世界预演”。

这样会带来：

- token 消耗失控
- 延迟越来越高
- 大量无意义事件
- 调试困难
- 世界容易自行跑偏

我们采用的是：

## 事件驱动世界

平时只推进确定性的状态。

例如：

- 时间前进
- 商店开关门
- 玩家移动
- 固定日程推进
- 已确定事件到期

只有真正需要角色做决定时，才调用 AI。

因此玩家感觉世界一直存在，但实际上世界只在必要节点上“思考”。

---

## 11. 时间推进

时间不是每一分钟都模拟。

例如玩家输入：

> 回家睡觉，明天早上再说。

系统不需要真的运行十几个小时。

而是：

```text
当前时间 22:40
↓
寻找 22:40 到次日早晨之间的重要事件
↓
处理真正需要发生的事件
↓
结算人物计划和世界变化
↓
跳转到第二天早晨
```

没有重要内容的时间段直接跳过。

这样世界能够运行几个月甚至几年，而不会被无意义的每分钟模拟拖死。

---

## 12. 长期上下文与记忆

聊天变长后，不把全部历史重新塞给模型。

世界资料本身长期保存，但每次调用只组装当前真正需要的上下文。

### 当前场景上下文

包括：

- 当前时间
- 当前地点
- 玩家当前状态
- 当前在场人物
- 最近几轮互动

### NPC 当前上下文

包括：

- NPC 核心人格
- 当前情绪
- 当前目标
- 与相关人物的关系
- 最近重要经历

### 主动知识检索

当系统发现缺少某段知识时，再主动查询长期资料。

不是简单地把“关键词触发”写死。

例如模型处理到：

> 林雨想起以前的同事周明。

当前上下文没有周明资料。

系统可以主动查询：

```text
周明
林雨 + 周明
旧公司
相关历史事件
```

只把查到的相关资料临时加入当前上下文。

因此世界历史可以越来越大，但单次模型上下文不需要一起增长。

---

## 13. 记忆不是简单删除

长期记忆采用分层思路：

### 近期记忆

保存较完整的最近经历。

### 重要记忆

对人物长期有影响的事件，例如：

- 表白
- 背叛
- 救命
- 严重争吵
- 创伤
- 重大承诺
- 关系改变

这些不会因为时间过去就轻易消失。

### 摘要记忆

大量普通经历可以压缩成阶段摘要。

例如十几次普通同事交流，可以逐渐归纳成：

> “过去两个月里，林雨逐渐习惯在工作遇到困难时向玩家求助，对玩家的信任有所增加。”

### 原始历史

完整事件依然可以长期归档。

需要的时候通过主动检索重新找到。

也就是说：

> **遗忘的是即时上下文，不一定是历史数据。**

---

## 14. 后续 Obsidian 知识世界

Obsidian 不作为第一阶段必须完成的功能，但从一开始就应该让世界结构兼容它。

后续接入后，世界运行可以自动生成知识节点。

例如：

```text
世界
├─ 人物
│  ├─ 林雨
│  ├─ 陈雪
│  └─ 玩家
├─ 地点
│  ├─ 公司
│  ├─ 酒吧
│  └─ 图书馆
├─ 事件
│  ├─ 公司争吵
│  └─ 文件失踪
├─ 事实
│  └─ 老板拿走了文件
└─ 每日记录
   ├─ 2026-09-03
   └─ 2026-09-04
```

节点之间互相链接。

例如：

```text
[[林雨]]
参与
[[公司争吵]]

[[公司争吵]]
发生于
[[公司]]

[[2026-09-03]]
记录
[[公司争吵]]
```

最终形成一种很特别的体验：

> 玩家在 Module4 中生活和行动，而另一边 Obsidian 中的世界知识图谱随着时间不断长大。

玩家可以在游玩之后打开 Obsidian，像翻阅一个真实世界留下的档案一样，看人物、关系、地点、事件和历史逐渐形成。

## 15. Obsidian 与游玩阶段的关系

建议分阶段实现。

### 第一阶段：先把世界跑起来

完成：

- 世界生成
- 地点系统
- 自由行动
- 时间推进
- NPC Agent
- 事件触发
- 世界裁判
- Facts
- NPC 认知
- 玩家认知
- 记忆
- 主动知识检索

确保一个小世界中有 2～3 个主要 NPC 时，可以稳定连续运行多天。

### 第二阶段：Obsidian 同步

把：

- 人物
- 地点
- Facts
- 事件
- 每日记录

自动输出到 Obsidian Markdown。

### 第三阶段：知识图谱体验

进一步加入：

- 双向链接
- Graph View
- Canvas
- 世界时间线
- 人物关系网络
- 地点关系网络
- 世界变化可视化

因此 Obsidian 不拖慢第一版核心玩法，但世界数据从第一天开始就为它保留结构。

## 16. 普通游玩模式与上帝视角

模块四 V2 应该有两个完全不同的观看方式。

### 玩家模式

强调沉浸。

只展示：

- 自己知道的事情
- 自己看到的人
- 自己听到的内容
- 当前场景
- 行动结果

### 世界管理 / 上帝视角

用于玩家自己整理世界、测试、开发和复盘。

可以查看：

- NPC 当前状态
- NPC 隐藏目标
- NPC 意图
- 未触发事件
- 世界事实
- NPC 错误认知
- 玩家未知事实
- 最近的后台事件
- AI 调度记录

两者严格隔离。

玩家模式不能因为系统知道秘密，就提前把秘密写进叙述里。

## 17. 一段完整的实际体验示例

### 18:20

玩家在公司看到林雨独自坐在休息区。

玩家输入：

> 我走过去坐到她旁边，问她今天是不是出了什么事。

系统只唤醒林雨。

林雨知道自己下午和陈雪发生过争执，但不知道老板已经拿走某份文件。

她回答：

> “没什么，就是下午和陈雪有点不愉快。”

玩家看到的只有这句话和她的表现。

后台则产生一个新的私人意图：

> 林雨今晚想联系陈雪确认一件事。

玩家看不到这个意图。

### 18:40

玩家离开公司回家。

这段移动主要由规则处理，不需要复杂 AI。

### 19:30

林雨的意图触发。

系统唤醒林雨。

林雨决定给陈雪发消息。

消息影响陈雪，因此陈雪 Agent 被唤醒。

两人的交流发生在玩家视野之外。

### 20:10

玩家收到林雨的信息：

> “明天有空吗？有件事想跟你说。”

玩家没有看到后台过程，却能够感受到：

**这个世界在自己离开以后依然继续变化。**

这正是模块四 V2 最核心的体验。

# 18. 当前已经确定的玩法原则

1. 模块四 V2 是自由沙盒，不依赖固定主线任务。
2. 世界采用事件驱动，不持续调用 AI 进行全世界预演。
3. NPC 使用相互独立的 Agent 认知。
4. NPC Agent 按需唤醒，而不是永久运行。
5. NPC 负责意图，世界裁判负责最终结果。
6. 玩家默认只看到自己的可感知视角。
7. 世界事实、NPC 认知、玩家认知必须分离。
8. 玩家可以自由输入行为。
9. 确定性的世界逻辑优先由规则处理，不浪费模型调用。
10. 长期上下文采用按需组装和主动知识检索。
11. 历史可以长期保存，但不会全部塞进模型上下文。
12. Obsidian 作为后续知识世界与可视化方案，从第一阶段就预留兼容结构。
13. 第一阶段先保证一个小型世界可以真正、稳定、连续地“活起来”。

## 19. 当前暂未定死的内容

以下内容留给下一阶段继续设计：

- 世界初始化生成器的具体输入流程
- 世界地图生成粒度
- NPC Agent 的精确内部字段
- NPC 意图的生命周期
- 世界事件优先级与冲突处理
- 多 NPC 同场景时的调用策略
