# Denova × 文字冒险平台 · 结合方案

> 分析日期：2026-08-11 ｜ 原稿 AI 2 ｜ 修订 2026-08-12 AI 1（5 条建议全部落地：Step0/Step1 优化 + 新增导出按钮 + Step3 账本对齐 Denova + Denova 路径已修）｜ 状态：方案层待拍板（未改平台代码）
> 用户诉求：Denova 硬核、样式好但工具杂乱、流程体验一般；平台对话写作对剧情内容关注更多。取长补短，一步步来。

## 0. 结论先行

- 两个工具不是竞争关系，而是**「创作工作台」与「剧情体验器」**的关系：
  - Denova 强在**写作工程化**（大纲→细纲→审稿→版本→Agent 自动化），弱在**剧情对话体验**（工具堆叠、流程繁琐）。
  - 平台强在**剧情即时体验**（角色卡/设定一键挂载、对话协议驱动、IF 线、场景图/Pixiv 一体化），弱在**写作工程化**（小说生成是"一次性"的，没有大纲/审稿/版本）。
- 结合的最优成本路径：**平台保持轻量入口，把 Denova 的深层能力按「渐进披露」移植进来**——平时还是现在这个对话冒险，想深入时打开导演台/大纲面板/版本面板。
- 不推荐现在去 fork Denova 改体验（Go 全栈，改造成本高；而且它已很硬核，缺的是入口精简，不是功能）。

## 1. 双方定位与设计哲学

| | Denova | 文字冒险平台 |
| --- | --- | --- |
| 定位 | 本地自托管 AI 创作工作室（写作 IDE + 互动叙事） | 纯静态单页对话式冒险平台 |
| 技术 | Go 单文件 + React Web（Apache-2.0 开源，可自编译） | 原生 JS SPA（无构建、无后端） |
| 设计哲学 | 内容优先、安静克制、一套系统两种模式、为连续创作优化 | 即开即用、功能即点即得、剧情/角色/设定一体化 |
| 用户体感 | 硬核、功能全、但工具杂乱、流程偏重 | 轻、快、对话感强、剧情关注度高 |

## 3. 差距分析：各自不可替代的点

**Denova 值得平台吸收的（按剧情价值排序）**
1. 故事导演台 + 状态系统 + 事件卡包 + TRPG 检定 —— 这是让"剧情更有戏"的工程化，直接命中用户诉求。
2. 大纲 → 章节组细纲 → 章节 的三级写作管线 —— 让平台小说生成从"一次性"变"可规划"。
3. 版本与变更账本 —— 冒险/小说改动可 Diff、可回滚，长线创作不怕改坏。
4. 审稿子流程（novel-standard/heavy）—— 生成质量可控。

**平台值得 Denova 借鉴的（远期）**
- 即开即用入口、角色卡/设定一键挂载、IF 线时间轴、Pixiv 一体化、多 AI 协作沉淀。

## 4. 结合方案（分阶段，每步可验证）

> 原则：**平台保持轻量主流程不变**；深层能力做成渐进披露（需要时展开），不做成第二套 Denova。

### Step 0 · 素材互通（数据层，~1 天）✅ 已完成（2026-08-12 AI 2）
- 目标：同一套**设定书**在 平台 ↔ Denova 都能用；**角色卡交由 Denova 原生导入，平台不转换**。
- 做（2026-08-12 已读 Denova 源码确认，省约 1/3 工作量）：
  - **设定书（lorebook JSON）→ Denova lore**：写单向转换脚本，写到 Denova 资料库 `.denova/projects/<book>/.denova/lore/items.json`（纯 JSON，结构 `{version, items:[{id,enabled,type,name,importance,tags,brief_description,keywords,load_mode,content}]}`）；保留反向 Denova lore → 平台设定书格式。
  - **角色卡（chara_card_v2）免转换**：Denova 原生支持导入 AI 酒馆角色卡（README 明说；Adelaine 项目即导入卡），**原"角色卡→lore"转换方向删除**，平台只负责把卡文件交给 Denova 导入即可。
  - Obsidian 素材库作为"人类可读层"继续用。
- 验证：把 2-3 本设定书（如火影忍者、龙与地下城）导进 Denova，游戏模式里能读到；把 Denova 新建的 lore 导回平台能挂载；角色卡直接导入 Denova 验证可识别。
- 落地：`tools/denova_lore_sync.js`（export/import/list 三模式）+ `tools/denova_bridge.py` v2（8097，POST /api/denova/export）；已实测：火影忍者 153 条 / 龙与地下城 68 条 / 异世界奇幻RPG 28 条导出并注册，反向回测 135 条可读；前端顶栏「🚀 导出Denova」按钮 + `exportToDenova()`；无头测试 9 项全过；测试工程已清理。
- **v2 质量修复（2026-08-12，用户反馈"导出太烂"后）**：剧情摘要改 LLM 生成（contextSummary 优先、失败降级原文）；四段设定解析分节输出；条目去重 + 类型排序；卡片 {{char}} 占位符清理。
- **v3 按模板重构（2026-08-12，用户要求）**：①**移除 NSFW 词条过滤**（用户明确"不要动我的 NSFW 词条"，词条书全量导出，上限放宽 200/500）；②按用户提供的「Denova 文件导入模板」生成完整骨架：CREATOR.md（剧情摘要+核心创作规则）/ ideas.md / setting/outline.md / setting/progress.md（回合数+当前位置+近期事件+局势+伏笔）/ setting/character-states.md（按角色卡逐角色生成）；③lore 条目对齐模板：importance（character→major 其余 important）、load_mode（character/faction→resident 其余 auto）、brief_description（"类型 名称。前3句"）。

### Step 0·b · 导出到 Denova 一键衔接（轻量入口，~0.5 天）✅ 已完成（2026-08-12 AI 2）
- 目标：平台内一键把**当前冒险（设定书 + 角色卡 + 当前剧情）**导出成 Denova 工程，用户想用 Denova 深层能力（大纲/审稿/版本账本）时直接跳过去，不必等 Step1/2/3 全做完。
- 做（纯前端，~0.5 天）：冒险菜单/设置加「导出到 Denova」按钮 → 按 Denova 工程结构打包：设定书写入 `projects/<name>/.denova/lore/items.json`、角色卡走 Denova 原生导入、剧情摘要放进 `interactive/` 与 `setting/`；写入 Denova 安装目录（路径常量统一 `<external-denova-installation>`，见 §8）。
- 验证：点按钮后 Denova 里能打开该工程、读到设定与角色、剧情可续写。

### Step 1 · 剧情导演台（平台功能移植，~2-3 天，**用户最关注**）
- 目标：把 Denova 的"导演思维"搬进平台在线冒险，剧情深度立起来。
- 做（全部纯前端，复用现有协议；**2026-08-12 已读 Denova 源码，直接复用其题材预设省约一半工程量**）：
  1. 协议扩展：现有 [PLOT]/[STATE] 增加 目标/压力/代价、事件卡包（[EVENTS] 埋设/推进/回收）、检定（[CHECK] d20+属性）。
  2. 全屏导演台：新弹窗集中展示 当前规划、目标、压力、代价、事件卡、检定结果、回合历史检索、行动建议。
  3. 状态系统：**直接复用 Denova 已有的按题材预设**——`story-director-modules/{actor-states,event-packages,rule-systems}/` 下 apocalypse / xiuxian / western-fantasy / infinite-flow / urban / default / trpg 七套模板（事件卡包每包 7-22 事件、rule-systems 含 6 种 DM 风格），作为导演台**初始词条库与事件卡/检定默认值**；平台按自身 26 类冒险类型映射对应题材模块（module_refs 可插拔组合 + `*_disabled` 独立开关），只做轻量裁剪/映射层，**不再从零手搓词条库**。
- 验证：无头回归 + 实跑一个冒险，确认协议解析、导演台读写、检定可玩、题材预设正确加载。

### Step 2 · 写作工程化（3-5 天）
- 目标：小说生成从"一次生成 N 章"升级为"大纲 → 章节组细纲 → 章节"，并带审稿。
- 做：新建"大纲/细纲"数据层（IndexedDB）→ 一键生成改为按细纲逐章生成 → 生成后可选审稿修订（novel-standard 思路，保留文风设定）。
- 验证：无头测试大纲→章节链路；用户试玩对比生成质量。

### Step 3 · 版本与变更账本（2-3 天）
- 目标：冒险/小说的每次 AI 改动可 Diff、可回滚、可跨重启 Undo。
- 做：快照升级 —— 存"变更账本"（类型/对象/范围/时间），界面加 版本面板（查看 Diff、恢复、Undo/Redo）。**账本格式直接对齐 Denova 的 `changes/ledger.jsonl` + `blobs/` 结构**（每行一条变更记录、blob 存正文差异），未来可与 Denova 互通。**复用 IndexedDB，注意容量（存储体检已有）。
- 验证：无头回归 + 存储体检不超限。

### Step 4 ·（远期/可选）Denova 体验优化
- 若素材互通后仍想用 Denova 本体：fork 源码做入口精简（或等官方更新），或把平台做成 Denova 的"剧情模式"前端。成本高，先不做。

## 5. 风险与取舍

- 移植要克制：用户已吐槽"工具杂乱"，导演台/大纲/版本都做成**按需展开**，默认界面不加按钮堆叠。
- 检定/事件卡包复杂度可控：纯前端实现，无后端；注意与现有存档兼容（新增字段带默认值）。
- Denova lore 格式**已于 2026-08-12 读源码确认**（纯 JSON：`projects/<book>/.denova/lore/items.json`；角色卡为 Denova 原生导入，无需转换）——Step 0 原"先读源码"前置项已消除。
- 版权与数据：素材互通只动本地文件，不涉及第三方。
