## 1. 整合目标与背景

### 1.1 背景与动机

当前用户同时维护两套独立工具：

- **文字冒险平台**：纯静态单页应用，以"对话即冒险"为核心，提供角色卡/设定一键挂载、LLM 对话协议驱动的剧情推进、IF 线时间轴、场景图、Pixiv 搜图、一键生成小说等能力，即开即用、轻量快捷。
- **Denova**：本地自托管 AI 创作工作室（Go 单文件 + Web 前端），以"创作工程化"见长，提供写作模式（大纲/章节组细纲/审稿/Change Review）、游戏模式（故事导演台/状态系统/事件卡包/TRPG 检定）、资料库、版本账本、Agent/Skills 自动化。

两套工具在角色设定管理、剧情推进、图像生成、上下文管理、版本恢复等方向存在功能重叠，但各有不可替代的特色。用户长期在两套工具之间手动搬运数据，体验割裂：

- 对话冒险产生的剧情无法直接进入 Denova 的写作管线；
- Denova 沉淀的大纲、细纲、设定无法反向驱动平台的文字冒险；
- 存档、素材、版本分别维护，无法形成单一可信数据源。

### 1.2 整合目标

将两个平台整合为一个统一的本地创作大平台，实现：

1. **一套数据**：设定、角色、剧情、章节、版本在平台与 Denova 间互通，消除重复维护。
2. **一条流程**：从灵感、设定、对话冒险，到小说成稿、审稿、版本回溯，形成连贯创作链路。
3. **双引擎协作**：文字对话引擎（即时剧情体验）与写作/导演引擎（深度创作工程化）互为输入输出。
4. **一致体验**：统一导航、视觉与操作流，模式切换顺畅，按需展开深层能力（渐进披露），避免工具堆叠。

### 1.3 预期收益

- 消除两套工具的重复劳动（设定/角色卡不再分别录入）。
- 对话冒险可一键沉淀为小说章节与设定文档（已实现：导出到 Denova v3，含章节、设定汇总、小说全文）。
- 小说大纲/细纲/审稿能力反哺平台，使平台小说生成从"一次性"升级为"可规划、可修订"。
- 版本账本统一后，任何改动可 Diff、可回滚，长线创作安心。

### 1.4 重叠内容比较与优化空间

| 重叠域 | 文字冒险平台现状 | Denova 现状 | 优化空间 |
| --- | --- | --- | --- |
| 角色/设定管理 | 知识库 50 设定书 + 39 角色卡、chub 下载、NSFW/讲述者分类、Obsidian 素材库 | 资料库 lore（items.json，resident/auto/manual、importance、brief_description） | 已完成单向转换（Step0）；后续做双向同步与"单一数据源 + 各端视图" |
| 剧情推进 | 对话协议 [NARRATIVE]/[STATE]/[CHOICES]/[PLOT]、IF 线时间轴 | 故事导演台、Actor State、事件卡包、TRPG 检定 | 平台移植导演台（Step1），协议层对齐，剧情结构共用 |
| 写作生产 | 一键生成小说（10 回合一章）、保留文风 | 大纲/章节组细纲/审稿（lite/standard/heavy）/Change Review | 平台写作管线升级（Step2），复用 Denova 大纲结构 |
| 版本与恢复 | IndexedDB 存档、快照、IF 线存档 | 本地 Git、changes/ledger.jsonl + blobs、跨重启 Undo/Redo | 账本格式对齐（Step3），未来可互通 |
| 上下文管理 | 压缩摘要、World Info 命中注入 | 渐进式上下文、检查点、来源展开 | 相互借鉴；平台保持轻量注入，Denova 保持深度管理 |
| 图像 | AI 场景图、Pixiv 搜图看图器（P1-P3）、保存成图 | 章节插画、互动图像、封面、图像预设 | 图像预设与成图目录互通，Pixiv 素材可进 Denova 工程 |

## 2. 用户偏好与定位

### 2.1 文字冒险平台的定位：剧情体验器

- 核心体验：**文字对话交互**，用户以第二人称参与冒险，追求即时性、沉浸感与剧情内容本身。
- 特色能力：角色卡/设定一键挂载、对话协议驱动、IF 线时间轴、场景图、Pixiv 联动、NSFW 分级与隐藏、离线小说游戏与火柴人可视化。
- 整合后保留：轻量主流程不变——打开即玩，对话即冒险。

### 2.2 Denova 的定位：创作工作台

- 核心体验：**写作创作与游戏模式**，面向长线创作，强调规划、审稿、版本与可复现。
- 特色能力：大纲→细纲→章节三级管线、Agent/Skills 自动化、故事导演台、状态系统、版本账本、资料库渐进式加载。
- 整合后保留：深度工作台能力按需展开，不稀释其工程化价值。

### 2.3 整合后的定位表述

统一平台以"**轻量对话驱动剧情、深度工作台承接创作**"为定位：

- 想快速玩一段冒险 → 文字对话模式（平台原体验）。
- 想把冒险写成小说、管理大纲、审稿修订 → 写作模式（吸收 Denova 能力）。
- 想跑"有导演的"冒险（目标/压力/事件卡/检定）→ 游戏模式（导演台）。
- 三者共享设定、角色、章节、版本，切换不丢失上下文。

## 3. 平台架构规划

### 3.1 总体架构

统一平台由**前端应用层、本地服务层、共享数据层**三层构成：

- 前端应用层：平台 SPA（现有 app/）为统一宿主，逐步承载写作模式与游戏模式面板；Denova 保留为独立工作台，通过导入导出与本地服务互通。
- 本地服务层：平台 HTTP 服务（8099）、Pixiv 桥接（8098）、Denova 导出桥接（8097）、Denova 本体（8080）、素材库生成脚本。
- 共享数据层：知识库（设定/角色）、Obsidian 素材库（人读层）、IndexedDB（平台存档）、Denova 工程（.denova/projects/）。

### 3.2 模块划分

| 模块 | 职责 | 承载位置 |
| --- | --- | --- |
| 文字对话模块 | 对话冒险主流程：角色卡/设定挂载、对话协议、IF 线、场景图、好感度/任务 | 平台 app/（现状保留） |
| 写作模块 | 大纲/章节组细纲/章节生成、审稿修订、文风保留、小说全文导出 | 平台新增（Step2 移植）+ Denova 写作模式 |
| 游戏模式模块 | 故事导演台、Actor 状态系统、事件卡包、TRPG 检定、离线小说线/火柴人 | 平台新增导演台（Step1）+ Denova 游戏模式 |
| 素材管理模块 | 知识库治理、角色卡管理、NSFW 分级、Obsidian 素材库、lore 互通 | 平台知识库 + 素材库脚本 + Denova 资料库 |
| 版本管理模块 | 存档、快照、变更账本（ledger + blobs）、Diff/回滚 | 平台 IndexedDB 升级（Step3）+ Denova 版本面板 |
| 图像模块 | AI 场景图、Pixiv 搜图看图器、章节插画/封面、成图保存 | 平台 Pixiv 桥 + ai-images + Denova 图像 |
| 共享设置模块 | API 配置（多模型）、NSFW 开关、主题、语言 | 平台设置页统一，Denova 设置独立保持 |

### 3.3 共享用户系统

本地单用户环境，无云端账号：

- 统一设置页：LLM API（endpoint/key/model，多厂商）、NSFW 显示开关、代理、Pixiv token、默认导出目标。
- 用户档案（角色名/偏好）在两个平台间保持一致（导出时携带，导入时应用）。

### 3.4 共享数据层

- **单一可信源原则**：知识库为设定/角色的权威源；Denova 工程为写作产物的权威源；平台 IndexedDB 为冒险存档的权威源。通过转换脚本与导出桥接保持同步。
- 同步链路（现状与规划）：
  1. 知识库设定书 → Denova lore（已实现，denova_lore_sync export）。
  2. 当前冒险 → Denova 工程（已实现，denova_bridge：设定/角色/摘要/章节/全文/设定文档）。
  3. Denova lore → 知识库设定书（已实现，denova_lore_sync import，反向）。
  4. 写作产物 → 冒险素材（规划：章节/大纲可挂载为 IF 线分支或新冒险设定）。

### 3.5 导航结构

- 平台顶栏一级入口：离线游戏 / Pixiv / 小说 / 提示词 / 角色卡 / 设定书 / Agent / 存档 / 剧情线 / 人物 / 导出 Denova。
- 规划扩展：新增「导演台」「写作台」「版本」一级入口，遵循渐进披露——默认折叠，需要时展开。
- 模式切换：文字对话模式 ↔ 写作模式 ↔ 游戏模式，切换由用户显式触发，状态与上下文保留。

## 4. 功能整合方案

### 4.1 去重逻辑

| 功能 | 处理 |
| --- | --- |
| 角色/设定管理 | 以知识库为权威源；Denova 侧通过导入/导出同步，不双写 |
| 版本管理 | 平台账本格式对齐 Denova（changes/ledger.jsonl + blobs），语义统一，存储分端 |
| 上下文管理 | 平台保留轻量压缩摘要；Denova 保留渐进式上下文；不互相复制机制 |
| 图像 | 平台场景图与 Pixiv 素材可直接进 Denova 工程；图像预设两套并存，导出时映射 |

### 4.2 互通逻辑

- **写作内容驱动文字冒险**：平台导出的章节/大纲可反向挂载——章节可作为 IF 线新分支的剧情底稿，大纲可作为新冒险的初始设定（规划）。
- **游戏进度关联对话**：导演台状态（目标/压力/事件卡/检定结果）写入对话协议扩展区块（[EVENTS]/[CHECK]），对话回合推进游戏状态，双向可见（Step1）。
- **素材互通**：知识库 ↔ Denova lore ↔ Obsidian 素材库三向同步（已实现单向，反向已具备）。
- **设定文档/小说全文**：LLM 生成中文设定文档与小说全文 txt 随导出进入 Denova（已实现）。

### 4.3 协同逻辑（双引擎闭环）

1. 灵感 → 设定（知识库/素材库）。
2. 设定 → 对话冒险（平台挂载，即时体验）。
3. 冒险记录 → 章节/摘要（一键生成小说 + 导出）。
4. 章节 → 大纲/细纲/审稿（Denova 写作管线深化）。
5. 大纲/设定 → 新冒险或 IF 线分支（反向驱动）。
6. 全程版本可回溯（统一账本）。

## 5. 用户体验一致性

### 5.1 视觉风格

- 统一采用深色主题与卡片化布局（平台现状），借鉴 Denova DESIGN.md 原则：内容优先、安静克制、状态信号明确。
- 平台新增面板（导演台/写作台/版本）沿用现有 CSS 变量与弹窗规范，不引入第二套皮肤。

### 5.2 账号与设置

- 本地单账号：设置页统一管理 API/NSFW/代理/导出目标。
- 导出流程携带用户偏好（主题、风格规则），Denova 导入时应用。

### 5.3 操作流一致性

- 所有异步长任务（生成摘要、设定文档、导出、章节生成）统一使用进度条/阶段反馈（已实现：denovaExportModal 进度弹窗，推广到其他长任务）。
- 模式切换显式、可逆、上下文保留。
- 高频动作靠近任务发生处；低频动作进入菜单/设置（渐进披露）。

## 6. 阶段性实施路线

### M0 · 基础互通（已完成）

- 内容：设定书→Denova lore（denova_lore_sync）；一键导出当前冒险（denova_bridge v3：设定/角色/摘要/章节/设定文档/小说全文/进度条）；Obsidian 素材库。
- 验收：导出工程在 Denova 可打开、可读设定与章节；反向导入可读。✅ 已通过端到端与 17 项无头测试。

### M1 · 剧情导演台（高优先级，2-3 天）

- 内容：对话协议扩展（[STATE] 目标/压力/代价、[EVENTS] 事件卡包、[CHECK] d20 检定）；全屏导演台弹窗；复用 Denova story-director-modules 七套题材预设映射平台 26 类冒险类型。
- 验收：无头回归通过；实跑冒险确认协议解析、检定可玩、预设正确加载。

### M2 · 写作工程化（3-5 天）

- 内容：大纲→章节组细纲→章节数据层（IndexedDB）；一键生成升级为按细纲逐章；可选审稿修订（保留文风）。
- 验收：大纲→章节链路无头测试通过；生成质量对比提升。

### M3 · 版本与变更账本（2-3 天）

- 内容：快照升级为变更账本（类型/对象/范围/时间，格式对齐 Denova ledger.jsonl + blobs）；版本面板（Diff/恢复/Undo/Redo）；存储体检不超限。
- 验收：无头回归；存储体检通过；跨重启 Undo 可用。

### M4 · 导航与视觉统一（2 天）

- 内容：导演台/写作台/版本一级入口；统一进度反馈；模式切换体验打磨。
- 验收：三模式切换顺畅；全站视觉一致；操作流 1-2 步可达高频动作。

### M5 · 深度协同（远期）

- 内容：章节/大纲反向挂载 IF 线与新冒险；导演台状态 ↔ 对话协议双向；Denova 体验精简（fork 或官方更新）。
- 验收：双引擎闭环端到端演示；用户全流程试玩。

## 7. 风险与备注

### 7.1 技术风险

| 风险 | 应对 |
| --- | --- |
| 纯静态前端无后端，深层功能依赖本地服务 | 本地桥接模式已验证（Pixiv/导出桥），继续按端口隔离扩展 |
| 存储容量：IndexedDB 存档 + 账本 + 场景图膨胀 | 存储体检已存在；账本 blob 按大小阈值落盘、定期清理；场景图可外链 |
| 两套工具版本/数据格式漂移 | 转换脚本版本化；导出/导入做格式校验与失败提示 |
| Denova 为 Go 闭源发布 | 深度体验改动需 fork 自编译（远期），优先在平台侧移植能力 |

### 7.2 体验风险

| 风险 | 应对 |
| --- | --- |
| 功能堆叠导致"工具杂乱"（用户已反馈） | 严格渐进披露：默认界面不增按钮，深层能力折叠展开 |
| 模式切换丢失上下文 | 切换前保存状态快照；切换后恢复当前位置与输入 |
| NSFW 内容跨平台展示尺度不一致 | 平台 NSFW 开关为准，导出/导入携带标记；Denova 侧按资料库标记管理 |

### 7.3 数据与安全

- Pixiv refresh_token、LLM API Key 属敏感信息：仅存本地配置文件，禁止写入日志/文档；导出桥接不转发凭据。
- 素材互通仅操作本地文件，不涉及第三方上传。

### 7.4 维护与协作

- 多 AI 协作：功能/踩坑记录继续维护于项目协作日志；结构性改动同步代码指南；无头回归覆盖核心链路。
- 导出质量治理原则：跨工具导出必须"内容治理"而非原样搬运（摘要生成、筛选、去重、中文化），防止垃圾数据污染目标平台。
