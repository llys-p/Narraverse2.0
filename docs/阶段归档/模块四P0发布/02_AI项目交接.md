## 3. Module4 核心循环

```text
创建世界
→ 导入角色
→ 绑定 source snapshot
→ Daily Preview
→ morning
→ afternoon
→ evening
→ Action
→ Judgment（仅风险行动）
→ Schedule Rewrite（成功改期时）
→ Facts
→ Settlement
→ 下一天
```

核心判断标准不是“模型能聊天”，而是世界状态能持续运行，玩家行动能改变后续状态，刷新/重启后事实不丢失。

## 4. Module4 架构合同

### World 与 Store

World 是模块四独立世界对象，包含标题、说明、玩家、时钟、地点、NPC、来源绑定、当前日预演、改期记录、Facts 和 dailyLogs。Store 只读写 `narraverse:module4:state`，负责 CRUD、自动保存、迁移和刷新恢复。不要把字段塞回 Module3 Adventure。

### NPC Runtime 与 Source

角色卡是 source；`world.sourceBindings[sourceRef]` 保存加入世界时的来源版本和最小快照。`world.npcs` 保存当前世界 Runtime，至少含 `id/sourceRef/name/mood/relation/goals/temporaryState/schedule`。Runtime 修改只作用于当前 world，不得写回原卡。不同世界用世界 ID 与 sourceRef 派生独立 Runtime ID。

### Clock 与 Energy

时段固定为 `morning`、`afternoon`、`evening`。主要行动按 `早 → 中 → 晚 → Settlement → 次日早晨` 推进；查看状态、世界、日志等免费信息操作不推进。消耗表集中在 `app/module4/core/clock.js`，当前默认闲聊/短移动 5、学习/帮忙 10、探索 15、训练 20、高强度活动 25。跨日由 Settlement 恢复到 maxEnergy。

### Daily Preview

`app/module4/ai/preview.js` 从当前 world 的 source snapshot、NPC Runtime、近期 Facts、世界标题/说明/地点摘要构造输入，经现有公共 `window.callLLM()` 请求，解析并校验每个 NPC 的 `npcId`、非空 mood/goal、完整三段对象和地点引用。当天有效条件是 `currentDay.previewGenerated === true` 且 `currentDay.day === world.clock.day`。同一天幂等；有限重试失败后保存 fallback 与 previewError，不能破坏世界。

### Schedule 与 Encounter

`Schedule.getEffectiveSlot()` 是日程读取的唯一入口，按“当前 Daily Preview/Runtime 原始 slot + 当前 world 的最新 rewrite”返回有效日程。Encounter 只比较规范地点 ID、当前时段和玩家地点；不在场是正常结果。不要在 UI 或 Encounter 内复制日程改写规则。

### Location

地点属于 `world.locations`，玩家保存规范的 location ID。`Location.get()` 同时支持地点 ID 和名称并返回规范地点对象；`Location.movePlayer()` 是底层原子能力，不承担完整行动语义。移动耗能和时间推进必须经 Action Executor。

### Action

推荐按钮、移动、主动寻找和自由输入都归一化成同一种 Action，再进入 `Action.execute()`。Action 至少区分 type、actor、目标、source、energyCost、advancesTime。免费查看类 Action 明确不推进。自由输入第一版保守解析，无法确认时可生成 custom，不要借此引入新的判定协议。

### Judgment

Judgment 位于统一 Action 管线中，先判断行动是否有风险；正常查看、移动、无冲突闲聊直接执行。风险行动使用可测试的综合评分，不引入 d20。结果严格使用 `success`、`costly_success`、`failure`、`critical_failure`。后果只做小幅 relation/mood/temporaryState 或玩家状态变化；失败不等于 Game Over。

### Schedule Rewrite

只有明确改期的 `invite` / `persuade` 在 `success` 后改写当前日后续时段。每条记录保留 NPC、day、period、originalSlot、replacementSlot、reason、sourceActionId、sourceOutcome、createdAt。原始 Preview 和 Runtime 不覆盖；所有后续相遇继续走 `getEffectiveSlot()`。

### Facts、Daily Logs 与 Settlement

Facts 记录关键、可持续的世界事实；dailyLogs 是面向玩家的短日结摘要，两者不等价。Settlement 是唯一跨日 authority：记录事件、补充未互动 NPC 的简短状态、清理 temporaryState、保留 relation/mood/source/rewrite/Facts、恢复精力、切到次日早晨和未生成 Preview。

### Persistence 与迁移

模块四使用独立 localStorage namespace，P0 不引入新 Go backend 或新存储层。迁移必须保留未知顶层和嵌套字段，不能通过重建对象静默裁掉未来字段；旧 Task 1～9 存档按归一化补齐 clock、locations、sourceBindings、facts、dailyLogs 等字段。

## 5. 已锁定的重要架构决定

- Module4 与 Module3 分开；只共享必要的 transport、角色资料入口和宿主嵌入，不共享 gameplay engine。
- Module4 代码主要位于 `app/module4/`，不复制 `app.js`，不恢复 Module3 的固定响应协议。
- 三段时间制是 P0 规则；Settlement 是唯一跨日 authority。
- 不使用传统 d20；判定采用确定性规则模型并支持测试注入。
- Daily Preview 每日生成一次，Schedule Rewrite 只在成功的明确改期行动后生效。
- Facts 是结构化世界事实，dailyLogs 是短回顾；不要用无限聊天历史代替 Facts。
- Source snapshot 与 Runtime 分离；源卡编辑/删除不得静默改变已有世界。
- API 只有平台共享配置；路径固定为 `window.callLLM()` → `state.apiConfig`，Module4 不设独立 endpoint/key/model。
- P0 使用 localStorage，容量治理留给后续阶段。
- P0 不新增 Denova Go gameplay backend。

## 6. 绝对禁止事项

- 不复制整个 Module3 Adventure/Game Engine。
- 不恢复旧 Director Console/导演台作为 Module4 玩法入口。
- 不把 Module4 主要逻辑塞回 `app.js`。
- 不新增 Module4 API 配置，不硬编码 endpoint、key 或 secret。
- 不把 Runtime 写回 Master/source，不复制整个 Module3 Adventure。
- 不让 UI 绕过 Action Executor 直接调用 Clock/Location/Encounter 完成玩家行为。
- 不让 AI 临时改写已经确定的日程或事实。
- 不在未经拆分和批准时开始 P1、战斗、技能树、多人或长期记忆。
- 不随便 reset、clean、stash、restore 或覆盖 `<project-root>`。
- 不根据旧聊天总结猜当前 Git/PR 状态；接手时必须重新查 GitHub、Git、源码和测试。

## 9. Shared API / Real Model

Module4 不保存第二套 API 配置。模型调用从 `PlayView.bindPreview()` 进入 `Module4.AI.Preview.startDay()`，再调用现有 `window.callLLM()`，由 Narraverse 共享 `state.apiConfig` 完成请求。endpoint、model 和 key 都属于共享 state；key 永远不能写入日志、PR、截图或归档。

已验证的非敏感模型信息：OpenAI-compatible HTTPS，provider endpoint 为 `api.deepseek.com`，模型为 `deepseek-v4-flash`。真实 Preview 曾返回 completed/non-fallback，随后完成推荐 Move Action 和刷新恢复。浏览器 origin 改变会改变 localStorage，不能把一个浏览器中的世界或配置当成另一个 origin 的数据。
