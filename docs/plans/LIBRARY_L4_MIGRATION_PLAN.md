# L4 按需旧资料整理（原迁移骨架的正式方向修订）

日期：2026-09-28。状态：**用户已确认不需要常规旧资料迁移；没有选定资料时，L4 以“无需导入、零数据变更”结束。**
本文件取代旧版“必须完成 inventory → preview → apply → rollback”的开发任务；旧版细节仍可从 Git 历史追溯，但不得据此启动写入。参考方向提案：`docs/l4-direction-revision-20260927` / `4bbbfe18`。

## 1. 目标与停止条件

L1 独立 Library + L2 受控读取 + L3 四模式消费构成作品设定库主产品闭环。L4 不阻塞 L3 的验收或发布，也不要求物理删除旧 World/Lore。

- 当前用户表示没有需要批量迁移的旧资料：**不做全盘盘点、自动转换、批量导入、旧入口退役**。这是 L4 的合法结束状态，不是“尚未完成大型迁移工程”。
- 将来用户具体指定一条有价值的旧内容时，才开始一次性整理。没有具体来源、没有用户核对，就不创建新 Library 条目。
- 原 World/Lore/Master 各自保留原件；不建立双向同步，不把剧情或运行状态写入 Library。
- 书籍、互动故事、Adventure 存档、Module4 存档、localStorage、Obsidian 与知识图谱都不属于这条整理路径。

## 2. 当前可用能力与不能假设的能力

| 能力 | 已核对的代码事实 | 使用约束 |
| --- | --- | --- |
| 配置管理 Agent 读取 | 可按权限读取总资料库 Master，以及当前作品的旧 Lore | 只读/提炼；不自动扫描所有作品或磁盘 |
| 旧 World 与外部文件 | 不存在已冻结的“资产管理 Agent 可按任意 World/文件路径读取并导入”的通用能力 | 用户从旧页面查看后提供选段，或另行明确授予受控来源；不得猜测 |
| 写入独立 Work Library | 已有编辑器与受控 API，可手动新建/编辑条目 | 配置管理 Agent 当前没有直接创建 Work Library 条目的工具；Agent 输出仅是待用户核对的草稿 |
| Library 来源形态 | `original/adaptation` 有库内正文；`reference` 正文取决于受控 Resolver | L3 运行时只解析已核验 Master reference；手填 `lore/world/file` 指针不能代替已存正文 |

## 3. 唯一默认流程：一次一条，用户核对

1. **用户选择**一条具体内容及用途。若没有选定内容，结束，不调用模型、不改数据。
2. **读取**：Agent 仅在现有权限内读取指定 Master/当前作品 Lore；其它旧内容由用户提供受控片段。失败时说明读不到，不编造来源或正文。
3. **草稿**：Agent 可帮助摘要、拆成少量角色/地点/规则/事件候选；不得自动判定同名即同一实体、自动合并关系、自动赋予常驻加载档位。只保留必要、受预算约束的选段。
4. **核对并保存**：用户检查正文、类型、加载档位及来源，再用现有 Library 编辑器创建 `original/adaptation` 条目。若是当前可解析且版本已核验的 Master，才可选择真正的 `reference`。来源仅记稳定 ID/版本/展示名/相对定位，不记绝对路径、密钥或未经证实的版本。
5. **验证**：用 L2 加载预览确认条目可读、档位与预算符合预期；必要时在目标模式单轮验收。旧来源保持不变，保存失败不得声称已入库。

此流程不需要新的迁移 API、长期 Registry、模型链或 Agent 自治写入权限。它是按需整理，不是自动迁移。

## 5. 重新开启自动导入开发的条件

只有用户指出**具体、数量明显超出逐条整理成本**的旧资料集合，并明确要求批量导入，才重新评估工具建设。需先记录：来源数量与版本、现有 Library 重复率、人工整理成本、目标库是新建还是合并、失败恢复要求及用户授权范围。用户未提出这些事实时，**不实施**预览后的 confirm/apply、备份平台、receipt/journal、批量导入或旧入口退役。

如果将来重新设计自动导入，仍需单独冻结选择/版本/CAS、备份、原子写、幂等和回滚，先在虚构副本测试，再就精确真实来源取得新的授权；当前 C1/C2a 并不自动满足这些条件。
