## 2. 这一大阶段实际做成了什么

| 阶段 | 已交付能力 | 必须守住的边界 |
| --- | --- | --- |
| World Workspace Phase 1–2B | 世界创建、实体与 Master 绑定、revision/CAS、手动刷新、用户确认的 AI 结构提案。 | World 原数据保留；AI 不直接写事实源。 |
| Phase 3.0–3.2 | WorldContext 只读快照/投影供写作、游戏、叙界、开放沙盒四模式使用。 | 剧情、进度不自动回写 World；见 [Phase 3.2 正式验收](acceptance/WORLD_WORKSPACE_PHASE3_2_FINAL_ACCEPTANCE.md)。 |
| 作品设定库 L1 | 作品库持久化、条目与来源、关系、事件、编辑及影响预览。 | Master 原件、Library 和旧 World 各守自己的职责。 |
| L2 | 常驻正文、按需目录、手选正文的版本受控读取、预算与主动预览。 | 只读预览不建运行状态、不自动扫库、不调用模型；见 [L1/L2 验收](acceptance/LIBRARY_L1_L2_ACCEPTANCE.md)。 |
| L3 | 明确选择 Library 后，四模式通过受控链路获得有界背景；旧 World/Lore 与新 Library 按 `legacy / library / none` 区分，不应暗中叠加。 | 运行中的读取有授权、固定版本和预算；设定正文不是剧情存档的第二份真源。见 [B5 工程验收](acceptance/LIBRARY_L3_B5_FINAL_ACCEPTANCE.md) 与 [真实模型取证](acceptance/LIBRARY_L3_CLOSEOUT_ROUND2.md)。 |
| L4 决策 | 用户当前无待搬的旧资料，故本期以“不导入、零数据变更”结束。 | 将来仅在用户指定具体来源时由 Agent 辅助拟稿、用户核对后用现有编辑器保存；不自动批量迁移或删除旧入口。见 [L4 正式方向](plans/LIBRARY_L4_MIGRATION_PLAN.md)。 |
| Kate 修复 | 保护标记差异与真实 revision 冲突分开报告；用户可比对后显式批准风险译文。 | 放宽标记不放宽 CAS；已提交代码不等于真实 7 条译文已应用。 |

现行产品关系可简写为：`Master 原件/用户原创内容 → 独立作品设定库 → 有界只读投影 → 用户选择的运行模式`。旧 World/Lore 暂时保留，不因 Library 成熟而自动迁移或删除；Runtime、Snapshot、临时授权不成为新的设定数据库。
