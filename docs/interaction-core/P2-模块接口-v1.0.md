# P2 · 语义与规则模块交接接口 v1.0

日期：2026-09-28 17:41。基线：`codex/interaction-core-fusion @ ee883e6`。本文件只固定 P2-A 与 P2-B 的交接面；P0 [融合契约](P0-融合契约-v1.0.md)仍是权威边界。

## 本轮切片与归属

- **P2-A / Interpreter**：读取玩家原文、已提交历史和服务端提供的实体目录，返回动作意图或澄清。只解释“试图做什么”，不判事实、难度、成功、状态变化或故事走向。由 WorkBuddy 小号在独立新模块实现。
- **P2-B1 / Facts + Rules**：在 P1 `DeliveryCore` 的副本结算和唯一 Commit 上，完成 `move → take → move → unlock`，保留原 `transfer`。由 TRAE 小号实现；只由该负责人修改 `laya_delivery_core.py`。
- **集成关口 / A**：在 A/B1 分别交付并审查后，接一条内部 `interpret → prepare_structured → commit → next state` 链。生产 HTTP、页面、Laya 与云端叙事此关口不接。
- **P2-B2**：随后补 `communicate/question`、`inspect` 和一个六档对抗动作。不要在 B1 中半做六档、关系写入或失败前进，以免把硬前提误当作可掷的难度。

## `TurnInterpretation` → `ActionIntent[]`

解释结果只有 `ready | needs_clarification | unsupported | invalid` 四种状态。只有 `ready` 可送入 Prepare；其余状态不创建可提交候选。`ready` 必须含 1–8 个按玩家表达顺序排列的动作。所有实体 ID 均须来自服务端本轮目录；别名可由服务端目录映射，不得让模型创造物品或目标 ID。需要目标而无法唯一确定时返回 `needs_clarification`，不暗选。

每个动作沿用 P1 字段：`id`、`operation`、`target_ids`、`object_id`、`mode`、`kind`、`content`、`evidence`。P2 扩两个可选字段：`depends_on`（更早的动作 ID 或 `null`）与 `when`（`always | if_achieved | if_not_achieved`，默认 `always`）。依赖只能指向本轮更早动作，不能构成环；条件不成立的动作记 `skipped`，绝不执行。没有条件时按顺序模拟，每一步读取前一步的模拟结果。旧 P1 请求不带新字段仍按原语义运行。

`evidence` 必须是玩家原文的逐字片段；解释器可以提供原文中多个片段，但输出到 P1 字段时用一段连续原文，无法给证据则 `invalid`。`negated / hypothetical / quoted` 不是物理尝试；隐喻威胁可解释为交流意图，不能默认转成 `attack`。`kind` 要真正传到规则层消费；一句“我说我给了你钥匙”不能据此转移钥匙。

P2-A 的结果只可携带意图、证据、歧义与解释来源。`difficulty`、`delta`、`outcome`、`degree`、已发生事实及客户端自报能力仍禁止。云端输出须经过本地 schema 与实体目录校验，失败直接返回 `invalid`，不使用关键词兜底。

## Facts / Resolver / Outcome

硬前提由服务端快照核验。阻止、资源不足、目标不明的动作不进入六档公式，不产生被阻止的物理效果。逐动作结果分开记录 `execution_status = skipped | blocked | attempted` 与 `degree`：前两者 `degree=null`；只有确实执行、且适合分级的动作才可用 `critical_failure | failure | partial_success | success | strong_success | exceptional_success`。无难度的确定性 `transfer/move/take/unlock` 可直接记录 `degree=success`，但仍明确其执行状态。不要把 P1 的旧三态 `degree` 当作六档已实现。

物品归属只写 `ic_world.interaction.objects.<id>.owner`。B1 的最小服务端场景包含 `tavern`、`old_well`、原先无人持有的 `cellar_key` 和一扇需该钥匙的门。`move` 只到服务端已知可达地点；`take` 要求物品在主体当前位置、当前无人持有且可拾取；`unlock` 要求人在门处、持有匹配钥匙、门仍锁着。询问得到线索不得直接移动、拾取或开门。每一步只在副本上模拟；Commit 继续由 P1 锁内重验、重算、原子发布，下一轮读取新状态。

## 接口保护与交接停点

P2-A 不能修改 `laya_delivery_core.py`、`laya_state_protocol.py`、`laya_bridge.py`；P2-B1 可修改 `laya_delivery_core.py`，但不能修改解释器或桥的 HTTP 路由。两方均不得改冻结翻译、能力档案、旧 benchmark、密钥与模型文件；不得另起可写 inventory、事件表或版本系统。若接口需要变化，先在各自交接报告写明冲突，停下交 A 裁决。

P2-A/B1 各自提交给 A 的是**未提交**改动、真实检查输出和未验证范围；不 push。A 在两方均过关后再负责集成、提交保存点。接 HTTP 前处理 P1 过期候选的明确回执语义。真实云端语义调用每项任务最多 3 次，记录模型、次数与成本；无可用配置时如实标未验证，不寻找或复制密钥。
